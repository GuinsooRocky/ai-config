后端结果分两类，前端处置相反。判据一句话：**空是结果，白页面是故障。结果别替（展示它），故障要替（防它）。**

- **空数据（空集 / 空列表）= 合法展示态。** 展示空态即可，**绝不**偷偷改写用户的选择（排序 / 筛选 / 参数）去回避"看起来空"。
- **会导致白页面 / 崩溃 / 渲染断裂（报错、undefined 炸组件、整页白）= 防御性兜底该上**，这种要替（默认值、空数组兜底、错误边界）。

**Why:** 2026-06-09 onlychat discover+tag：为回避"发现+标签→后端返回空集"，前端把用户选的排序静默改回 recent-hits —— 把一个合法空态当故障兜，反而制造了"选标签就被弹走"的新 bug。用户（2026-06-26）纠正：不是"凡空就不兜"，是分清空态（别替）和白页面（要替）。

**How to apply:**
- 看到"前端因为后端可能返回空，就改 sort / filter / 跳转"→ 停，这是把空态当故障，删。
- 不确定是空态还是白页面 → 看"不兜会发生什么"：展示个空列表 = 空态（别替）；整页白 / 报错 = 故障（要替）。
- 真要兜的是"后端给的东西会让页面崩"，那些保留。相关 [[feedback-fix-within-reported-scope]]
