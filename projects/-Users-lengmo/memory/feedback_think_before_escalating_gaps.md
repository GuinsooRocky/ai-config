把群里/评论里别人提出的问题（如「未过审付费图占额度没法释放」）包装成「产品缺口，要提 PM/后端」并在多轮对话里反复提，被 owner 顶回：「又是别人发现的问题然后让你抓到了把柄？自己不先想想？肯定后端会做删除，只不过现在没做好。」（2026-08-27，paid-image 项目）

**Why:** 后端说「X 还没做、流程很长」是排期陈述不是拒绝；PRD 若已写清终态（删除规则齐全），中间的不一致只是开发过渡态。把过渡态当缺口上报，既浪费协作方时间，也显得在挑刺。同类前科：[[feedback_dont_declare_infeasible]]（盲判「不可行」）。

**How to apply:**
1. 想上报「缺口/矛盾」前先推演终态：PRD/设计有没有定过终态？定过 → 大概率是过渡态，闭嘴等落地。
2. 「还没做」「没做好」一律读成进行时，不读成否定。
3. 同一个问题提过一次没人接 → 不重复提；写进项目文档挂账即可，别升级成催办。
4. 前端对前端的依赖（组件插槽、契约对齐）找对应前端同学，别把压力递给 PD/PM。
