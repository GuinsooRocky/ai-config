工作群里的改动说明（onlychat 老板 09-07 反馈）：产品看不懂技术过程，要按「5 岁小孩能看懂」的标准写。

**Why：** 09-07 搜索浮层修复说明三轮返工。老板原话：「上面的描述就是问题了 → 页面应该显示搜索页，但是显示了首页；后面只是在说问题延伸的问题 → 再按一次返回才真的离开，离开什么到了哪里？」以及「这个过程好像说多了，产品可能看不懂」。我写的「页面记录带着首页的身份、浏览器把它当首页恢复」「只影响 Mobile 搜索浮层」全被判读不懂。

**How to apply：**
- 每个问题一条，固定句式：做了什么动作 → 应该看到什么 → 实际看到什么。延伸现象要说清「到了哪里」，不留「才真正离开」这种悬空词
- 原因只一句，用生活比喻（「浏览器以为你还在首页」），不出现 history / pushState / 路由 / 实验组 / 浮层这类词
- 「影响范围」拆两句：用户侧谁碰得到（手机端所有用户 / 电脑端没有）+ 数据侧要不要处理；「只影响 X 模块」会被读成「基本无影响」
- 修完的效果先说「回到 X 之前的表现」，再列具体表现；技术代价（整页加载慢一点）、没变的部分（返回键/蒙层照旧）不写
- 参考样板：Wei 08-31 那条「问题 / 背景 / 影响范围」结构，见 [[feedback_no_jargon_plain_product_language]] [[feedback_work_group_messages_user_sends]]
