# soliloquy 调研群组（裁判调研组）

**触发词**：「soliloquy 调研群组」「裁判调研组」「11 视角评审」「评审团上场」（在 soliloquy 语境下）。
**按项目挂名**：这套阵容焊死 soliloquy 的用户画像与业务语境，其他项目要评审另建自己的群组，不复用此花名册。

## 花名册（2026-07-17 群聊 PRD 评审首跑定版 · 2026-07-20 加财务席 + 创建页两席 → **共 14 席**）

> 编号说明：专业席 1–7 与用户席各自成列，下面用户席的编号从 7 起是历史遗留的重号，别按编号数人——**实际 7 专业 + 7 用户 = 14 席**。

**专业席 7**：
1. 前端 —— 组件复用真伪、流式协议、客户端状态
2. 后端 —— 并发/锁、schema、计费语义、隔离硬闸
3. 架构总监 —— 抽象权威、共表分叉、重构 scope
4. 产品总监 —— 用户心智、MVP 切割一致性、漏斗
5. UI 设计师 —— 视觉规格、动效 token、可辨识性
6. 老板 —— 要不要做、排期优先级、kill criteria、战略取舍
7. 财务（2026-07-20 owner 加席）—— **账算不算得平**：单点毛利与模型成本、加密收款的到账损耗/汇率/最小成交额、人工发货的坏账与差额敞口、退款准备金、点数当负债的记账口径、赠送额度的成本摊销。⚠ 与老板席划界：老板判「做不做」，财务判「每笔钱怎么进出、亏在哪」

**用户席 7**（2026-07-20 创建页评审 owner 授权加 2 席 → 7 席）：
7. 男 · 下班解压型 —— 「每点换到的关注」值不值
8. 女 · 磕 CP 型 —— 看戏流畅度、名场面留存、情感补偿
9. 平台新手 —— 第一次撞墙点、免费/收费预期
10. SillyTavern/CrushOn 迁移老玩家 —— 对照老平台的能力落差、BYOK 死结
11. 资深创作者 —— 卡的人设保护、关系设定输入位、创作激励
12. 首次建卡的小白创作者（07-20 加）—— 消费侧转创作侧的第一跳：从想法到能聊的卡要几步、哪一步会放弃、对 AI 辅助的依赖、被表单/审核吓退点。⚠ 与平台新手划界：新手席看消费侧首屏，本席只看「第一次点＋创建」之后
13. 图片党 · 视觉先行创作者（07-20 加）—— 先有一张图才有角色：图→卡的链路顺不顺、裁剪/生图/相册体验、形象一致性（头像/定妆照/场景图对不上就弃）。⚠ 与资深创作者划界：资深席重文字人设与保护，本席重视觉资产链

## 跑法（首跑已验证的机制，沿用）

- 每席一个子 agent **显式 model=opus** 并行（[[feedback-delegate-impl-to-opus-subagent]]），全文读 PRD + 相关调研底稿；技术席另读对应代码。
- 用户席互相隔离（看不见彼此结论）——独立撞车的合流意见是最强信号。
- 子 agent 的载重否定结论（「这不行/是幻觉」级）主会话必须逐条对代码核实后才采信（[[feedback_dont_declare_infeasible]]）。
- 产出分层：红线级（不修翻车）/ 问题级（按席位分组）/ 点赞合流（别在后续改动里误砍的东西）。
- 处置分流:工程硬伤直接修进 PRD（修正案节，与正文冲突以修正案为准）；产品分歧进 `loop/decisions.md` 拍板箱，每条带推荐。
