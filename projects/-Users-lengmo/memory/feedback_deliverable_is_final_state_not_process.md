交付的文档（HTML 报告、方案、PRD）**只写「现在是什么、该做什么」**。我的复核过程、"上一版我判错了"、"这是第几次同类错误"、逐轮 audit 章节——一律不进正文。

**Why:** 用户原话「我理解 html 应该是最终结果 但是你很喜欢把过程放进去」。过程记录对我有意义（可追溯、显得诚实），但读者要的是拍板依据；混在一起会让 700 字能讲清的卡片胀到 1000+ 字，还把真正要看的警告淹掉。2026-07-30 六类卡顿源报告改到 v3.2 时，决策台 13909 字里堆了三轮复验章节和一堆 `.corr` 撤回段。

**改已写好的文件 = 覆盖清理，不是追加。** 用户原话（2026-08-08，soliloquy-SEO-文档集.html）：「既然要改一定是之前的不满意，只要覆盖掉之前不满意的了，才叫干净」——他不想读文档时还得在脑子里过一遍「之前怎么设计的、后来怎么改的」，那等于**多学一遍错误知识**。我上次写这份文档时被提醒过、没照做：改动全用「（2026-08-07 §0.9 一致性修订）」「原文默认 → 替换成」「旧口径废止表」「v2.4 存档评审 tab」的方式加在旁边，结果 432KB 里有一整个 tab + 两节 + 40 处旁注在讲历史。

**How to apply:**
- 改文件的默认动作是**改写那一句/那一节本身**，不是在后面补一条「已修正为…」；改完全文搜一遍日期戳、版本号、「原/旧/此前/不再是/已解除/修订」
- 评审报告、对抗审计这类「当时为什么这么改」的东西：结论落进正文后**整个删掉**，要留就单独一个文件
- 区分两类信息：**「这条结论还没验证 / 照抄会出事故」= 最终状态，留**；**「我先前算错了 37.2KB 其实是 21.6KB」= 过程，删**
- 版本间差异最多留一张紧凑对照表（给看过旧版的人），只写「改成什么」不写「谁错了」
- 过程记录要留就单独落一个文件，别塞进交付物
- 判据：删掉这段，读者做决定会不会做错？不会 → 删

**PRD/设计文档同理（2026-07-18 立规）**：过程叙事（谁拍的、哪天翻案、评审团怎么说、「已拍记录/拷问实录」小节、~~删除线~~翻案痕迹、「原口径已过时」注记）全部清掉，拍板结果直接改写进对应正文小节，语气写成「本来就这么设计的」。当时把 owner 拷问过程写成「§6a 已拍记录」放进 soliloquy 个人页 PRD，owner 原话「我不需要拷问实录这种东西……最终我只要一份原文章的PRD」。决策过程要留痕就放 QA 台账或 decisions.md。待拍板小节可以留（那是未来的事，不是过程叙事）。

**学习笔记/转写稿同理（2026-09-24 第三次）**：给播客做「摘要 + 原文」笔记时，我把「本文来源：Whisper 转写 17 段×8 分钟、术语按 shownote 校正」「标点为机械加入、去标点后逐字一致」「每 8 分钟一个切块时间戳」「（转写里名字听不清）」「（5 处截图，文字取自小宇宙文稿）」「（还有几处没截图，待补）」全写进了文件，owner 一句「笔记只要结果不要过程」。这些全是**我怎么做出来的**，读者回看笔记时一个都用不上。切块时间戳、校验方式、来源工具、"听不清/待补"标注一律不进笔记；章节定位只留内容本身的时间轴（shownote 章节）。

**owner 要拿去执行的方案 = 施工单（2026-09-30，soliloquy 文档整理方案）**：owner 原话「等你改完我就拿着这个开始做了，你要改的是很明确怎么做的文档」。第一版我只写了方向和理由（改哪类东西、为什么），他要的是每处改动的文件、原文片段、改后全文、验证命令和预期输出。我的做法（我的理解，不是他的原话）：原文片段逐条回仓库核对存在；能先在临时拷贝上跑通的（补丁、检查脚本）先跑通再写进去；需要他拍板的单列一节，不挡前面的步骤。**交付就是他点名的那一个文件**：同一轮我把补丁另存成第二个文件放在旁边，被骂「合成一个文档，你非得多写一个文件干嘛」。配套的补丁、脚本、清单一律嵌进那一个文档（附录 + 一条从文档里取出来用的命令），不另建文件。
