用户打磨口播稿/文字时给的各种反馈，表面是不同维度（要专业、要深入浅出、别土、别情绪、别文绉绉、别报菜名），他本人明说"这些都是在说品味"。把每条当孤立规则去满足会顾此失彼——专业了就生硬、浅白了就掉价、删情绪删成干巴。改字先问"这句有没有品味"，而不是逐条勾规则。

品味 = 该专业时精准立得住（术语/机制/出处不塌）+ 该浅白时小白接得住 + 不土（无"死命令/废了/一坨"）+ 不端（无行云流水/蛛丝马迹式成语堆砌）+ 不喊情绪 + 不报菜名。

## 切面一：口语化 ≠ 注水（去 AI 味先辨"去味还是注水"）

高频毛病：把源文章里**干净准确的一句**反射性"口语化处理"，加"怕你听不懂"的奶味填充，越处理越 AI 味。典型（都被当场抓）："零件出奇一致"（书面 flourish 强凹口语）、"五个大件"（原词就是干净的"五大件"）、"加一个专门记东西的地方"（把"一份磁盘记忆"奶声奶气绕一圈）。用户原话"那些文章每一句都没有 AI 味，你为什么不学一学"。**优先贴源文章的 register**（干净、密实、术语准确），别拿大白话稀释。这是 [[feedback_no_jargon_plain_product_language]]（大白话）的边界：准确术语能立住就别绕。

**去注水 ≠ 变短，是拿承重细节换掉空话**（2026-06-24 用户示范）：我在例子前搭台子（"先给这个 loop 派个真活，我们天天干的那种"——全是预告+表态零信息），用户改成一句平引子 + 塞进更密的真技术细节（监控禅道 bug 单→流转→检测→改→验→提交→通知），细节替你证明"任务真复杂、但 loop 搞得定"。三条硬规律：① 引子要平、功能化，张嘴就上具体的；② 密度给在信息上不给在口水上；③ 别预报结构（"拆开看五个功能"提前抖答案），留悬念。

**必查「不啰嗦」**（2026-06-24 单列）：啰嗦=同一个意思说两遍（"做了收不回来"+"不可逆"）+ 表态填充句（"这不是吓唬人""说白了"）+ 对仗金句（"替你干活也在替你犯错"）+ 例子铺太满。一个意思一遍，承重细节留、空话和重复砍。

## 切面二：技术分享 = 精准 × 共情，缺一不可

- **精准**：每个概念给得起定义和边界（LLM=决策核心 / harness=模型外的整套链路 / loop=由验收线决定再不再来一轮）。
- **共情**（用户原话拆两层）：①听得懂 ②他自己也这么经历过——把技术链路的某一步焊到听众真实发生过的瞬间。**不是打比方让他"想象"，是点破他早已亲历、只是没说清的那个时刻。**

只精准没共情=像念文档；只共情没精准=像听段子。验证过的样例（claude-code-workflow-talk）：失忆→"你离开一会儿回来它忘了十分钟前写的代码"；模型会完美地写错→"泡杯咖啡回来它把十几个文件全改了、全跑通、但全错"；缓存边界→"账单莫名跳水可一行报错都没有"。写完逐句自检：缺精准补准定义，缺共情补亲历瞬间。

**保用户原话（反复踩坑，2026-06-22 强化）**：用户给了自己的口播/大白话时**原样用，别加工**——别顺成排比、别塞连接词、别凑对仗。根因都是过度润色（举手开场、"在座都是明白人"、"三支柱"、口号化、目录被顺成排比全是反例）。只清语音转文字的标点毛刺，语气/选词/啰嗦都保留他的。判别 AI 味：三件套报菜名、破折号接金句、"不是X而是Y"对仗、正确废话——出现就是我加的，删。

## 切面三：结构化内容直接给表格

"N 个条目 × 理由/属性/对照"默认给表格（留什么 | 为什么），别写成散文让用户在脑子里重新拆。口播项目里表格**以真 `<table>` 内联进稿子当可视内容**，`.mic` 只留一句引子；绝不加"念/不念/deck slide"类小标注；表本身别当口播逐字念，最多口头挑一行展开。

## 切面四：工作群里问人 = 只留问题本身

2026-08-28 我写给后端的飞书消息被用户重写，长度砍掉一半，"这才是人话"。我的版本把「提问」写成了「汇报」，四类多余的东西全要删：

| 我写的 | 为什么删 |
|---|---|
| 铺垫（"接上面那条"、"我翻到的只有 CharacterImage.is_paid…"） | 我在自证做过功课，对方不需要 |
| 我的处境（"本地界面整片出不来，只能拿假数据走查"） | 我的麻烦不是他的麻烦 |
| 替对方安排（"大概什么时候能给"、"我先按现在形状写接口到了再换"、"这条归延泽要的话我去找他"） | 我心里的账，写出来是给对方压任务 |
| 给别人派活（@Alice 写成三行请求） | 一句话带过就够 |

另一条硬规律:**给对方能直接执行的标识,别给内部黑话**。要开权限就给 `zhanghao@peekaboo.tech`，不给 `has_activated_paid_image_privilege` 让他再翻译一次。

用户的成品形状：@人 → 编号问题 → 三行 bullet 列事实 → 一句 @旁人 → 一句可执行请求。没有一个字解释为什么问。

准备高利害对话本身仍走 [[crucial-conversations]] skill，这条只管「问题写多长」。

## 切面五：口语稿要去 AI 味（不只是"不官腔"）

2026-09-20 反讲文档末节（会上照着念的话术）第二轮仍被判：「这种煞笔话能不能不要 能不能去个 ai 味」。
被点名的两句：「我今天讲三件事：这功能长什么样、PRD 没写清的地方我怎么拍的、还有……」
和「开始之前对三个词，后面我都按这个说」。

**AI 味的具体形状**（写给人念的东西一律先扫这几条）：

| 病灶 | 例 | 真人怎么说 |
|---|---|---|
| 编号宣告开场 | 「我今天讲三件事：」 | 直接进内容 |
| 关于说话的说话 | 「后面我都按这个说」「我说一句自己的判断」 | 删掉，直接说那句判断 |
| 破折号 `——` | 满篇 | 口语里没有，换句号断开 |
| 「一句话：」「简单说」「换句话说」 | 起手式 | 删 |
| 三段排比 / 每段总分总同构 | 「成了几个、排除了几个、跳过了几个」这种真枚举可以留，但段落骨架别整齐 | 长短不一 |
| 书面连接词 | 因此 / 也就是说 / 值得注意的是 | 就是 / 挺 / 反正 / 顺手 |

要提醒的事**说进那句话本身**：「还有个地方我改了 PRD 的写法，得跟你说一声：……」，
不要另起一行写导演提示。同一轮还砍掉了「被问到时怎么答」的问答预案——**预设别人会问什么，本身就是 AI 味**。
