2026-09-10 用户看 DAG 学习手册（learning-handbook 骨架的第一份产物）1/3 后原话：「什么怎么学啊什么的都很没用，我看了 1/3 还是不知道 dag 定义是什么」。

**Why:** 第 0 章整章是「怎么学这本书」（目标—检验表、八块说明、先做再读、答案别先开），主题词「有向无环图」被当已知词直接塞进「一句话要背」，全书没拆开讲过；每章又先讲故事、先做题、再讲概念——零基础读者在盲做。把教学框架（生成效应 / 先做后讲）套过了头，学习法本身占了内容的位置。

**How to apply:** 任何学习材料（手册 / 课 / 讲义 / 教我学 X）：
1. 第一屏就是主题词的字面定义（DAG = 图 / 有向 / 无环），配一个用户天天在用的例子（import 图、CI needs:、Excel 公式）；默认读者零基础
2. 每章第一屏一个「定义」块，大白话 + 本章要用的词全给名字，之后才是情境 / 先做 / 展开
3. 「怎么用本书」类元说明 ≤3 行，折叠到第 0 章末尾，不许独占一章
4. 「先做」放定义之后、展开之前
5. 块是写作顺序不是卡片：页面上除练习和代码，全是正文段落；每章带底色 / 边框的容器 ≤2，块名不上页面，不做每章开头的「学完你能」框。09-10 第三版加了定义块后用户看第 6 章开头四个框叠一起：「看的眼花缭乱的，感觉是为了做 card 把很多碎的东西拼一起」。搜过：Mayer 连贯 / 信号原则（处处加框 = 没信号）、Quantum Country 把问题嵌在连续正文里，都不支持卡片式排法
6. 小标题稀着用：5 万字以内 4–6 章、目录 ≤8 条、一章 h3 ≤3，其余写成段首加粗。第四版又被指「文章没多长，但是你就是喜欢搞碎，搞成小标题」（9 章 + 4 附录、57 个 h3）→ 并成 5 章 + 附录 + 冷测，h3 降到 15。
   ⚠️ **这条不限学习材料，所有长文 HTML 都算**（反讲 / 调研稿 / 方案）：2026-09-20 推荐模型批量管理反讲首版按 PRD 章节一节一条目录，17 节 43 个标题，owner 看目录截图原话「小标题太多了 我看到哭想」。**源文档有十几个章节 ≠ 目录要列十几条**——相邻章节合成一节，原章节号靠徽章/节内 h3 承载。已写进 [[onlychat-prd-reflection]] SKILL.md 核心原则 6.5
7. 表格 ≤2、练习不做表单：第五版被判「表格很蠢，练习中的输入也很蠢」——32 张表（规格 / 对照 / 填空）改成列表段落，textarea / 勾选框 / 进度条 / localStorage 全删，练习 = 问题 + 折叠对照。
   ⚠️ **表格那半条同样不限学习材料**：2026-09-20 反讲 20 张表被判「能不能少一些表格 除非特别需要的」。
   判据——**只有「必须并排看才成立」的二维对照留表**（A vs B 逐项差异、N 项 × 属性矩阵），
   单纯「名称 | 说明」的清单一律转 `<ul>`（`<li><b>名称</b> —— 说明`）。那次 20 → 5 张。
   ⚠️ 转换时当心**表头承载语义**的对照表（列头就是对照双方的名字，如「弹窗 4 | 弹窗 5」）：
   机械转列表会丢掉「哪句属于哪边」，这种要么保留表格、要么改写成带主语的段落

8. **彩色底框别用来「包装」正文，元说明一律删不是压缩**：2026-09-20 反讲末节（会上照着念的话术）
   配了绿底框 + 每段下面一行灰字导演提示 + 开头「按 20 分钟备：开场 1 分钟·正文 12 分钟…」，
   owner 三连否：「文案不需要这些乱七八糟的」「这种背景板（不要）」「也不需要这些屁话」。
   判据——**底框只给性质不同的东西**（警示 / 待决策），同一性质的正文再重要也用朴素段落 + 段首加粗；
   「这份东西怎么用 / 该看多久 / 这时候该指哪儿」这类**关于内容的内容**直接删，不是折叠。
   第 3 条说的「≤3 行」是上限不是配额，绝大多数时候正确答案是 0 行。已写进 [[onlychat-prd-reflection]] 原则 6.7

   ⚠️ **同一天栽三次，因为规则每次只落到被点名那一处**：6.7 只管末节话术 → 话术开头
   「先说清楚几个词」被判「说这个话就是蠢」→ 改完话术，正文台账导语「共 23 条…下面逐条写清
   怎么拍的、依据是什么、风险在哪」又被判「这个也不需要吧」。**元说明是全文级禁令**，
   判据一句话：**把这句删掉，读者少知道了什么？答「没有」就删**。同批清掉的还有
   「先把映射表摆出来，后面所有讨论都建在这张表上」「这节是全 PRD 信息密度最高的一张表」
   「我把它拍平成可直接写代码的形态：」「先不看 PRD，用一个故事讲清楚」。
   例外只有**结论型**的一句（「全部问题已拍完，不需要外部输入」），那是信息不是导航。
   已写进 6.10 + 自检 16（带 grep 命令）

   ⚠️ **同日复发，因为只修了被骂的那一节**：6.7 只管话术节，全文没管——同一份反讲正文
   9 节塞了 50 个带框容器（21 warn + 14 note + 2 big-card + 5 card + 7 qrow + 1 scope），
   平均一节 5.5 个，owner 原话「真的太乱了 全是乱七八糟的格式 这是skill的问题吧」。
   **定性判据不够，要配额**：一节带框容器 ≤2；`.note`（「中性说明」蓝框）这类组件直接删掉，
   它就是个「正文也能装框」的口子。**而且根因常在样式不在数量**——`code` 的灰底圆角方块
   让 260 个标识符变成马赛克，去掉 `background`/`padding` 后同样数量就不糊了；
   `warn`/`scope` 去底色只留左竖线，6 个连排也不是 6 块色斑。已写进 6.8 / 6.9 + 自检 15/16，
   底稿 `assets/handbook-template.html` 的 CSS 同步改掉（改 skill 文字不改模板 = 下次照样生成）
