代码注释不是事实，是别人留下的线索。可能过时、可能抄错、可能从一开始就脑补 — 尤其是引用外部章节号 / PRD / Figma 节点 / 别处文件路径的注释。

**Why:** 实际踩过的坑：`EditNotesFrame.mobile.tsx` 注释里写"0 个有效条目时点击进 §8.10.2 二确"，把 PRD 原文翻完整份发现根本没 §8.10.2 这个章节号，是写注释那人脑补出来的。如果信了注释里的章节号，就会跟着复述错误信息给用户，错上加错。

**How to apply:**
- 注释只当 hint（"这里写注释的人当时想表达什么"），不当事实
- 任何"PRD §X.X 怎么说" / "Figma 节点 X:Y 怎么画" / "为什么这样写"必须翻原文核对，不能凭注释下结论
- 写注释断言后端行为（"后端会返回 X / 后端逻辑是 Y"，不只 PRD/Figma）：要么贴核实来源，要么明写"未核实推断"，不能把推断焊成事实（2026-06-09 "后端 discover 叠 tag 返回空集"就是未核实推断写成定论，误导了后续修复）
- 注释看起来"特别详细、特别帮你解释逻辑"时尤其警觉 — 越像解释的注释越可能是脑补
- 写新注释前问自己：3 个月后这段还会准确吗？不准确就别写（参考 [[feedback_writing_comments_rules]]）

**反方向同样成立：PRD 也不是「代码现在是什么样」的真相。**

写审计报告 / loop 装载单 / 工单的「病灶」段时，**必须是 grep 出来的，不能是读 PRD 推的**。PRD 说「应该有 X」≠ 代码里现在有 X，也 ≠ 代码里没有 X。

2026-07-21 soliloquy 一天内栽两次（都是我照 PRD 清单写工单、没回代码核）：
- 「群聊断流半句丢了、钱照扣」→ 施工方回代码一查，07-20 那批债务清理**早修好了**，整条是假待办
- 「AI 正在思考只有一个菊花在转」→ 那一态**压根没有菊花**，就是一行斜体字，工单的前提不存在

两次都靠施工 agent 自己查代码才没照错前提硬做——**那是运气，不是机制**。工单写得越具体，下游越可能直接照做。

**待拍项上桌前同理（2026-08-16 被顶）**：把审计挖出的「未完项/矛盾项」拿给 owner 拍板前，必须先查代码现状再给推荐——可能早做了、可能早废了、可能跟现行实现完全岔开。只凭稿子自述出选项，等于让 owner 对着过期前提拍板。owner 原话：「你应该查完代码，然后思考一下，再推荐我呀」。


**替 owner 起草对外消息前，核实门槛再高一档（2026-08-28 一天栽两次）**：

owner 让我写飞书群消息问后端，我照走查记录和手册直接写了三条「后端缺的字段」+ 一条「账号没权限」，他发出去后当场被打脸两次：

| 我断言的 | 实际 | 我该做的 |
|---|---|---|
| 账号没付费图权限 | 后端回「公司邮箱一直有权限」。`Not eligible yet` 出自 `PaidImageCard.tsx` 的**三个达标条件**没过，跟白名单是两回事 | 走查记录里那句「(真实权益态=未开通)」是当时的**推断**，我当事实转述了 |
| 缺 canMarkPaid | `toPaidImageVM.ts:379` 前端早就自判了，注释原话「proto 里根本没有这个字段，等它等不到」 | grep 一次就知道 |
| 缺付费审核状态 | `submittedKindOf()` 早把 `reviewV2.displayBehavior` 映射成三档，schema 明写「别再加一个」 | grep 一次就知道 |
| 缺实时额度 quota | ✅ 这条是真的 | — |

owner 原话：「cnm 坑我」「原来你没核代码就让我去问了？」

**规则**：给自己看的结论错了只是返工；**让 owner 拿去问同事的结论错了，烧的是他的信誉**。所以凡是要出我这个进程的断言（飞书消息、PR 描述、工单、给 PM 的问题清单），每一条「我们缺 X / 对方没给 Y」都必须有一条 grep 结果垫底，垫不上就不写进消息，改成「我没找到，帮我指一下」。

尤其防：**走查报告 / 审计报告里带括号的推断**（「(真实权益态=未开通)」这种）——它长得像结论，其实是当时的解读，转述前必须回代码验。见 [[feedback_truncated_output_is_not_ground_truth]]。
