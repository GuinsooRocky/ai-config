# 学习手册

汇报把结论排给人看；学习手册让人在一个例子上把结论自己做出来。全文每一段都要能回答一句：**读者在这里做什么**。答不上来的段落是汇报，不是课。

## 何时使用

- 用户说「学习手册」「学习模版」「做成课 / 讲义」「教我学 X」「把这份汇报改成学习材料」
- 用户已经有一份按知识来源排章、段段是结论、自测只复述上文的文档，想把它变成能学的
- **不**用于：读源码仓库成书（codex 侧 `study-repo-as-book`）、只要排版（codex 侧 `longform-html`）、抓链接出要点（`analyzer`）、小红书 / 公众号（`xhs-writer`）、一句话讲明白（`eli5`）

## 输入

| 项 | 要求 | 缺了怎么办 |
|---|---|---|
| 主题 | 一句话 | 问 |
| 原料 | 文章 / 调研稿 / 已有手册，多多益善 | 没原料先跑 `analyzer` 或 `deep-research` |
| 学习者 | 默认「会编程的自学者」 | 按默认走，不问 |
| 贯穿例候选 | 学习者自己手头的真活优先 | 从原料里挑一个 10–15 个元素规模的具体对象 |

原料是汇报式文档时：**知识一个字不丢**，改的是排法和读者动作。先把它的正文按段标上「进哪一章、当哪一块」，再动笔。

## 执行步骤

### 步骤 1 · 倒推：先写目标—检验表，再排内容

1. 写 4–8 条「学完能 + 动词」：判定 / 手算 / 写出 / 找出 / 改坏 / 设计 / 对照。「理解」「掌握」不算动词。
2. 每条配一个检验：**换场景的任务**，不是复述。判据：学习者能否靠背上文答出？能 → 不合格。
3. 这张表放在第 0 章，且最后一章逐条回收。

```
❌ 学完你应该能理解关键路径
✅ 学完你能：给一张 12 节点带估时的图，手算 ES / LS 表，指出关键路径和最松的节点
   检验：把 N9 估时从 3h 改成 1h，说出关键路径挪到了哪条线
```

### 步骤 2 · 选一个贯穿例

- **只有一个**，具体到有名字、有编号、有数字（12 个节点、3 个 slug、7 小时）
- 学习者自己的真活优先；没有就从原料里造一个，标明「以 X 为原型，细节简化」
- 第 0 章介绍它，之后**每章至少一次**在它身上算、写、改、破；最后一章把它做成玩具跑起来
- 中途不许换例。要举反例时写「换一张图」，做完回到贯穿例

### 步骤 3 · 按能力阶梯排章

- 章名 = 学完能做的事（分辨 / 派活 / 判完成 / 回退 / 抢活），**不是知识来源**（图论 / 构建系统 / Airflow）
- 来源降级成章内的「这招从哪借的」小框
- 后一章必须用到前一章的产物；脚手架递减：前几章演示带全步骤，后几章只给任务和答案
- 历史 / 术语 / 延伸阅读放附录，不放开头——没概念可挂的历史读了就忘
- **章数按篇幅定，不按知识点定**：5 万字以内的手册 4–6 章，目录（含附录）≤ 8 条；一个知识点不到 8000 字就并进邻章。附录合成一条，冷测单独一条
- **表格是例外不是默认**：全书带边框的表 ≤ 2，只留真正的数表（贯穿例的节点清单、算出来的 ES / LS）。对照、规格、术语、事故分析一律写成列表或段落（`<li><b>项</b>——说明</li>`）
- **练习是「想一想 + 折叠对照」**，不是表单：不放输入框、勾选框、进度条、localStorage；读者在脑子里或自己的笔记里答，展开对照
- **小标题稀着用**：一章里 h3 只给「练习」和并章时的分界，其余全部写成段首加粗（`<p><b>要点。</b>正文……`）。每千字 ≤ 1 个小标题

### 步骤 4 · 每章定义先行，再八块，顺序固定

**块是写作顺序，不是页面上的卡片。** 页面上定义 / 情境 / 概念 / 演示全是正文段落，块名不出现；只有三个 h3（练习 / 这里容易想错 / 本章加进规格的）和一个小标签（先试试）。每章有底色或边框的容器不超过 2 个（练习、代码）。Mayer 的连贯与信号原则：每段都加框加标签，等于没有信号，读者眼花；Quantum Country 把问题嵌在连续的叙事正文里，不做分区块。

读者默认**零基础**：主题词本身（DAG、验证器、租约）要从字面拆开讲，不许当已知词直接用。第 0 章第一屏就是主题词的定义，不是「怎么学这本书」。

| # | 块 | 读者做什么 | 一句写法 |
|---|---|---|---|
| 0 | 定义 | 一屏内知道这词是什么 | 大白话、一屏内、字面拆开、带一个熟悉的例子；本章要用的词全在这里给名字 |
| 1 | 情境 | 感到痛 | 贯穿例上出一件事，3–5 行，先有问题再有概念 |
| 2 | 先做 | 猜 / 算 / 写 | 拿刚给的定义动手，留输入框；答案折叠。放在定义之后、展开之前 |
| 3 | 概念 | 读 | 从「你刚才做的结果」讲起，术语最后给名字 |
| 4 | 演示 | 跟着走 | 在贯穿例上带中间步骤走一遍，表格给全 |
| 5 | 自己动手 | 改 / 破 / 写 | 2–3 个变体：改参数、加一条边、把它弄坏；每个带勾选框 |
| 6 | 这里会错 | 对照自己 | 本章的误读当场放，不攒到附录 |
| 7 | 回头题 | 用旧解新 | 1–2 题，用前面章的东西解本章场景 |
| 8 | 攒规格 | 记一行 | 「本章给规格加了什么」，学习者自己的规格表逐章长 |

细节和 ❌ / ✅ 对子见 `ref/chapter-skeleton.md`，写章之前 Read 一遍。

### 步骤 5 · 检验三层 + 密度

| 层 | 放哪 | 判据 |
|---|---|---|
| 章内 | 自己动手 | 换场景 / 换参数，不是复述；答案不能在上文 3 段内逐字找到 |
| 隔章 | 回头题 | 用第 N−2 章之前的东西 |
| 冷测 | 附录 | 隔三天再做；全部新场景；不给提示；≥10 题 |

- 密度：每 ~1000 字一处需要动手的停顿（Quantum Country 是每 ~1500 词一组问题）
- 答案一律折叠（`<details>`），先做后看
- 目标—检验表里的每一条，在正文里能指到具体哪个练习

### 步骤 6 · 终局：搭 + 破

- 一个 100–200 行的玩具实现（学习者的主力语言），把前面攒的规格跑起来
- ≥5 个破坏实验，每个三列：怎么破 / 期望看到 / 对应哪章
- 「我的规格」（逐章攒的）vs 「参考规格」的差异表——参考规格是答案卷，不是正文

### 步骤 7 · 落 HTML

- 底稿用 `assets/learning-handbook-skeleton.html`（在 codex 侧 longform-html 视觉基线上加了学习组件），双击能开，无 CDN
- 组件：`.define` 定义 / `.scene` 情境 / `.try` 先试试（问题 + 折叠对照）/ `.do` 练习（`.ex` 问题 + 折叠对照）/ `.trap` 这里会错 / `.spec` 记进规格 / `.borrow` 这招从哪借的；没有输入框、勾选框、进度条
- 输入框和勾选框走 `data-key` 持久化到 localStorage；**进度 = 做完的练习数，不是滚动位置**；目录每章显示 `done/total`
- 图标一律内联 SVG 线性图标，不用 emoji
- 去 AI 味口径同 longform-html：不写「首先 / 综上 / 值得注意的是」，一个意思说一遍

### 步骤 8 · 交付前自检

过一遍 `ref/checklist.md`，报：文件路径、目标—检验表、练习总数、冷测题数、是否保留了原文件。

## 输出约束

- 单文件 HTML，双击能开；第 0 章第一屏**必须**是主题词的字面定义 + 贯穿例介绍，目标—检验表折叠或放章末；末章含搭 + 破；附录含冷测
- 每章第一屏**必须**是「定义」块（`.block.define`），之后八块**必须**齐全，块名固定（情境 / 先做 / 概念 / 演示 / 自己动手 / 这里会错 / 回头题 / 攒规格），第 1 章的回头题可以指向第 0 章
- 「怎么用本书 / 先做再读 / 答案别先开」这类元说明**不许**超过 3 行，**不许**独占一章；折叠或放第 0 章末尾
- 「先做」**必须**在「定义」之后、「概念」展开之前；答案**必须**折叠；贯穿例**只能一个，不许**中途换
- 全书带边框的表**不许**超过 2 个；练习里**不许**出现 textarea / checkbox / 进度条 / 本机存储，答案**必须**用 `<details>` 折叠
- 目录**不许**超过 8 条；一章里 h3 **不许**超过 3 个（练习 + 并章分界），其余小标题**必须**写成段首加粗
- 每章有底色 / 边框的视觉容器**不许**超过 2 个（练习、代码）；块名（定义 / 情境 / 概念 / 演示 / 回头题 / 攒规格）**不许**出现在页面上，「学完你能」**不许**做成每章开头的框
- 原料里标了来源的事实和数字照抄，**不改**；来源清单进附录
- 覆盖用户已有文件前**必须**先 `cp` 一份到 `~/.Trash/`，交付时说明
- 交付前**必须**过一遍 `ref/checklist.md`，不过的当场改

## 示例输出

2026-09-10 的《DAG 任务板 · 学习手册》（`~/Desktop/DAG任务板-学习手册.html`）是第一份按本骨架做的产物。第 0 章目标—检验表的两行：

| 学完你能 | 检验 | 练习 |
|---|---|---|
| 给一张 12 节点带估时的图手算 ES / LS 表，指出关键路径和最松的节点 | 把 N9 估时 3h 改成 1h，说出关键路径挪到了哪条线 | 2-a |
| 给 12 个节点各写一条验证命令，认出写不出来的那几个并改写声明 | 把 N12 的验证器改成不清理测试账号，说出第二次跑会发生什么 | 3-b |

第 0 章第一屏的「定义」块（09-10 第一版没有这块，用户读了 1/3 还不知道 DAG 是什么，第二版补上）：

```
DAG = Directed Acyclic Graph，有向无环图。三个字各管一件事：
图：一堆点，点和点之间连线。一个点 = 一件活，一条线 = 「谁要等谁」。
有向：线带箭头。N2 → N3 读作「N3 要等 N2 做完」。
无环：顺着箭头走回不到出发点。A 等 B，B 等 C，C 又等 A——谁也开不了工。
你天天在用：import 图、package.json、CI 的 needs:、Excel 公式。
```

第 2 章「先做」块（在定义之后、展开之前）：

```
在第 0 章那 12 行里圈出「没有前置」的节点；再圈出它们完成后能开工的第二批；
最后凭直觉估一个总时长写在框里。
[textarea data-key="c2-try"]  [details: 对照]
```

末章五个破坏实验之一：

| 怎么破 | 期望看到 | 对应哪章 |
|---|---|---|
| `board.link(N12, N1)` 让 N1 依赖 N12 | 抛错「成环: N1 已经能到达 N12」，边不写入 | 02 派活 |

## 反模式

1. **装饰当骨架**——挂上「学完你应该能 / 先想一下 / 自测」三样课的装饰，底下还是按来源排的综述。判据：把装饰全删掉，剩下的能不能当汇报读？能，就还是汇报。
2. **章按知识产地排**——图论 / 构建系统 / 工作流当章名。改成能做的事。
3. **自测复述**——问题的答案两段前刚说过。改成换参数、换场景。
4. **历史放开头**——读者没有概念可挂。放附录当故事。
5. **例子各举各的**——每节一个新例子，读者要反复重新进入。只留一个贯穿例。
6. **终局给表看**——完整规格作为正文让人读。改成读者先攒、最后对照。
7. **进度条量滚动**——读到哪不等于学到哪。量练习完成数。
8. **术语先于例子**——标题是术语，正文再解释。先在例子上做，最后才给名字。
9. **先做放错位置**——放正文后是复习不是生成；放定义前是让零基础读者盲做。位置：定义之后、展开之前。
10. **知识量缩水**——为了「像课」删原料。原料一字不丢，改排法。
11. **把学习法当内容**——第 0 章整章讲「怎么学这本书」，每章开头讲「先做再读、答案别先开」。09-10 DAG 手册第一版就是这样，用户原话「什么怎么学啊什么的都很没用，我看了 1/3 还是不知道 dag 定义是什么」。元说明 ≤3 行，定义先行。
15. **表格当正文**——32 张表：三列「项 / 说明 / 借自」的规格表、五列对照表、填空表。读者原话「表格很蠢」。除节点清单和 ES / LS 数表，全部改成列表和段落。
16. **练习做成表单**——textarea、勾选框、进度条、localStorage。读者原话「练习中的输入也很蠢」。练习就是一个问题加折叠的对照，读者自己想。
14. **小标题当段落**——5 万字排成 9 章 + 4 附录、57 个 h3，读者原话「文章没多长，但是你就是喜欢搞碎，搞成小标题」。并章到 5 章，h3 只留练习，其余改段首加粗，h3 从 57 降到 15。
13. **块做成卡片**——每章 9 个带底色、带图标标签的框（定义 / 学完你能 / 情境 / 先试试……）一个接一个。09-10 第二版就是这样，用户原话「看的眼花缭乱的，感觉是为了做 card 把很多碎的东西拼一起」。块是写作顺序；页面上除练习和代码，全是正文。
12. **主题词当已知词**——「有向无环图」四个字从头到尾没拆开讲过，只出现在「一句话要背」里。读者默认零基础，主题词从字面讲起，配一个他天天在用的例子。
