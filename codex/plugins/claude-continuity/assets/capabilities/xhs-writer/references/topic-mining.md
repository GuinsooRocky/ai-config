# 选题线细则（挖选题 + 数据复盘）

> 本文件只在选题线触发时加载。选题方法论本体（HKR 质检法、选题交集模型、选题来源、爆款分类）在 `content_methodology.md` §1-2，本文件不重复，只管**执行流程**。

## 定位

用户是 300 粉技术博主（2026-05 重启后断更），断更根因不是不会写，是**没选题、启动成本高**。本线把"日常素材 → 拿起来就能写的选题卡"变成低成本动作，管道：daily-recap 产矿 → **本线选矿** → 本 skill 的长文线/小红书线成稿。

三条内容线（用户既定，不新增）：**AI 编码**（素材最厚，日报里全是）/ **项目**（onlychat、MK、肉类大全的真实过程）/ **生活**（程序员日常视角）。

## 模式 A：挖选题（默认）

**输入**（至少一样，没有就问用户要）：
- daily-recap 日报文本或路径（`~/.claude/skills/daily-recap/ref/samples/` 最近几份）
- analyzer 产出的分析卡片（做对标参考）
- 用户随口给的想法/经历片段

**流程**：
1. 若 `~/Desktop/PRD/小红书/选题权重.md` 存在，先读它——历史数据好的选题类型优先排
2. 按三条线扫素材：一个真实细节（踩坑/反转/数字）= 一个候选
3. 每个候选过 HKR 质检（标准见 `content_methodology.md` §1）：**≤1 项命中直接丢弃，不出卡**
4. 产出 **2-4 张选题卡**，按预估价值排序

**选题卡格式（strict）**：

```markdown
## 选题卡 #N：<选题一句话>
- **线**: AI 编码 / 项目 / 生活
- **HKR**: H✓ K✓ R✗（及格）/ 全✓（S 级）
- **角度**: <切入角度，一句话>
- **目标人群**: <谁会点开>
- **钩子**: <标题方向 1-2 个，不是定稿标题>
- **素材指针**: <来自哪份日报哪条 bullet / 哪段真实经历——必须真实可溯>
- **预估难度**: 低（素材全齐直接写）/ 中（要补 1-2 个细节）/ 高（要额外做实验/截图）
```

用户挑中哪张，直接接本 skill 对应产出线成稿（公众号长文走第一~四步，小红书 9 图走 `xiaohongshu.md`）。

## 模式 B：数据复盘（用户手贴数据才进）

**输入**：用户从创作者后台抄来的数据（小眼睛/点击/赞/藏/评/涨粉）。

**流程**：
1. 按漏斗归因：**小眼睛（曝光）→ 点击率（标题钩子）→ 赞藏比（内容质量）→ 涨粉（人设认同）**——每篇定位卡在哪一环
2. 跨篇找模式：哪条线、哪类角度、哪种钩子的数据好
3. 结论写进 `~/Desktop/PRD/小红书/选题权重.md`（不存在则创建）：**追加带日期的复盘记录 + 更新顶部权重结论区**，不删历史记录、不整文件重写

## 硬规则

- **素材指针必须真实可溯**：每张卡的素材必须指向日报真实条目或用户亲口说的经历。**绝不**编"你可以分享一下 XX 经历"式的空选题——没素材的选题 = 启动成本高 = 继续断更
- **复盘数据只来自用户手贴**，拿不到后台就不进模式 B，**绝不**估算或编造数据
- **一次最多 4 张卡**——卡多 = 把选择成本还给用户
- **价值观闸**（同「核心价值观 · 有所为有所不为」）：钩子可以有悬念，**不许**承诺正文没有的东西
- **选题卡是本线终点**：不在选题环节直接动笔写正文，成稿走对应产出线
