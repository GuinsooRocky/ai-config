# 课程设计思路 — yangbo 怎么写一本技术小册

他的 AI Agent 小册能拆到 161 章，不是堆料，是一套可复用的方法。

## 1. 章节粒度：一个动作 = 一章
拆章标准**不是知识量**，而是「这一步是不是一个独立的、可验证的工程决策」。
所以「引入 Tailwind」「引入 shadcn」「约定设计规范」「类型共享」各自单列成章。
判断要不要单开一章，问：这一步能不能独立验证它跑通了？能 → 单列。

## 2. 单章内部结构（已被正文修正）

> ⚠️ 早期推断是「痛点→是什么→边界→怎么做→坑→总结」六段式。Step 2 用归档正文核对后
> **证伪**——「边界」「坑」并不单列成段。真实结构如下：

**编号小节递进 + 末尾总结节**：
- 章内用 `0、序` `1、…` `2、…` … `N、总结` 顿号编号切小节，小节数 3-6 不固定。
- **痛点**并进开头一句话或 `0、序`，不单列。
- **「是什么」**：开篇给一句本质定义（「闭包的本质就是局部数据共享」）。
- **「怎么做」**是主体：讲一步 → 贴代码文件（`api.ts`/`index.tsx` 多文件标签）→ 贴可交互预览。
- **坑 / 边界**不单列成段，塞进 `NOTE` / `ATTENTION` 高亮框穿插（「这是反模式，不建议这样用」）。
- **末尾固定「总结 / 小结 / 最佳实践」节**，bullet 列点 + 预告下一篇。

实战章（架构尊享版）更极端：几乎没有连续散文，是「一句话场景 + 大段带注释的分层源码」。

## 3. 概述章只建地图，不写实现
「概述章 / 总览章」专门让读者知道全貌、知道每章在体系里的位置，**刻意不写可运行代码**。
- 001（学习心法）：教读者怎么用这本书。
- 021（LangChain 架构总览）：讲 `@langchain/core → LangChain → LangGraph` 三层关系。
他明说第一遍阅读就该「先建立地图」。

## 4. 实战章是「收束器」，不引入新概念
实战章（003、115）的作用是**把前面若干章的能力放进一条真实可跑链路**。
115 明确说「不是又学一个新能力，而是把前 13 篇的能力放进一条真实链路」。
实战章只验证「知识叠加后的工程价值」，不夹带新知识点。

## 5. 难度爬坡靠「同一问题反复加深」
不是线性堆新料，是回到同一主题加一层复杂度：
- Agent 线：021 单 Agent → 022 多 Agent
- Hono 线：076 是什么 → 101 与 Next 集成
- 类型线：Zod 章 → 141 类型共享 → 144 代码组织
他称之为「系统复杂度变化，不是高级感升级」。

## 6. 把「为什么」当独立教学单元
大量「为什么」式标题：「AI 应用为啥适合 monorepo」「为什么单开一篇讲 ai/rsc」。
先讲清动机，再讲做法。动机值得单独一章。

## 7. 用一个贯穿全书的真实产品当锚
全书锚在「AI 电子伴侣（小薇）」这个产品上。003 章就把产品、五道工程鸿沟、四层架构定死，
后面每章都能挂回这个场景，避免孤立知识点。
写小册前先定一个贯穿性的真实产品。

## 8. 新手友好靠即时补课，不靠省略
遇到底层名词（IncomingMessage、冷启动、catch-all 路由）临时插一段「如果你第一次接触，先解释一下」，
用 NOTE 块标注。难度不靠跳过，靠就地补一小段。

# 跨 10 本小册的验证与补充

上面 8 条提炼自《ai 电子伴侣》。横扫他另外 9 本小册（React18/19 基础与架构版、
React 原理面试、React Query、zustand、JS 核心进阶、RN 跨平台进阶）的目录结构后，
验证结果与新发现如下。

## 哪些规律跨全集成立

- ✅ **拆章粒度细**（强）：React Query 把「更新请求」拆 3 章、RN 把「ScrollTabs 实现」拆 7 章。
- ✅ **概述章只建地图**（强）：每个大模块开头几乎必有「总览/全景图/定位/如何理解体系化」章。
- ✅ **实战章是收束器**（强）：实战章一律带「实践：/实战：」前缀，永远排在一组知识章之后。
- ✅ **同一问题反复加深**（强，这是他最核心的进阶手法）：架构尊享版实战篇用**同一个接口数据场景**连加 10+ 层约束（并行→依赖→缓存→分页→与 zustand 结合……）。
- 🟡 **锚一个贯穿性产品**（部分）：实战类小册成立；偏理论的《JS 核心进阶》锚的是「知识树」、《React 原理面试》锚的是「源码本身」，不是产品。
- ✅ **单章结构已修正**：Step 2 归档正文后核对，「六段式」证伪，真实是「编号小节 + NOTE 框 + 总结节」（见上方第 2 节）。

## 新发现的规律（《ai 电子伴侣》里没有的）

- **每本第 1 章固定锁版本号**（React@19.2.0 / RN@0.83.0 / zustand@5.0.3…）。他不写「永不过时的抽象教程」，而是绑定具体版本，靠改版本章维护。
- **他自己就在写「SKILL.md」章**：React18/19 架构版、zustand 都有一章直接叫 `SKILL.md`——他已主动把小册设计成「能喂给 AI 复用」。
- **文件名前缀是一套元数据系统**：`核心XX` `hardXX` `试读XX` `限时免费XX` `NewXX`——难章、试读章、新章一眼可辨。
- **主线纯净，旁支进「扩展章节」**：JS 核心把组件化/TS/其他收进显式的「扩展章节」分组，不混入主线。
- **直播录屏单独成章并前置**：课程是「文档 + 直播」双载体，直播答疑（含职场、简历话题）也编进目录。
- **每本结尾互相导流**：10 本是一个有意编织的产品矩阵，不是孤立的书。

## 难度分层设计

- **基础版 vs 架构尊享版**：基础版按「API 清单」组织（怎么用 + 小实践）；架构尊享版按「问题难度阶梯」组织（复杂真实场景的架构决策 + 读组件源码），章节带 `hard` 标记。
- **React18 vs React19**：不是替换，是互补——18 讲经典 hooks 心智，19 只讲新增范式（use/Suspense/Compiler/form action）。
- **跨小册进阶链**：JS 核心 → React18 基础 → React19 基础 → Query/zustand → 架构尊享版 → 原理面试；RN 是横向跨端扩展，AI 电子伴侣是应用方向扩展。
