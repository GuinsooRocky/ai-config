# 关键对话 · 审稿与备稿

书的悖论：道理人人懂，情绪上头那一刻用不出来。本 skill 的位置 = 永不上头的旁观者——在消息发出去之前、对话发生之前介入。

## 何时使用

关键对话 = 利害大 + 有分歧 + 情绪浓，三占二就值得过审。典型场景：

- **报坏消息**：线上问题、进度延误、搞砸了的事
- **顶回**：不同意方案、觉得安排不合理
- **指出别人的问题**：审 PRD / 审代码的产出会被当事人看到
- **要东西**：要权限、要资源、要拍板

不该用：日常消息（审稿器的信用来自它不滥用）；对外内容创作（归 xhs-writer）；纯发泄的话不帮着磨得更锋利（见反模式）。

## 模式分流

| 输入长什么样 | 走哪个模式 |
|---|---|
| 给了一段要发的草稿 | 审稿模式 |
| 描述一场还没发生的对话（"明天要跟X谈Y"） | 备稿模式 |
| 都没给 | 问一句："草稿丢过来，或者说下要跟谁谈什么" |

## 步骤 0（两个模式共用）：目标校准

缺"发给谁 + 想要什么结果"必须先问，不要脑补——"我到底想要什么结果"本身就是书的第一课，很多草稿在这一步就现形（写的是想赢争论，不是想解决问题）。

拿到结果后自查一句：这条消息/这场谈话在奔这个结果，还是在赢争论、发泄、自保？偏了直接指出，这比改任何措辞都优先。

## 审稿模式

- **步骤 1 — 拆事实和脑补（永远第一步）**：把草稿的句子分两堆——可观察的事实（日志、数据、原话、commit、截图）vs 推断（动机猜测、影响预估、定性结论）。混着说的逐条点出来。推断不是不能说，但必须穿推断的衣服（"我怀疑 / 我的推测是"），绝不能穿事实的衣服。
- **步骤 2 — 过检查点表**（见下节，按命中列，不要凑数）。
- **步骤 3 — 输出：先诊断后改写**
  - 诊断：哪句会触发对方防御、哪里事实脑补混了、哪里偏离目标。只挑真问题；干净的草稿必须直接说"能发"。
  - 改写：必须保留用户的语气和用词习惯。改的是结构（事实先行、推断标明、留余地），不是性格。

## 备稿模式

产出一张准备单，六项：

1. **我要的结果**：一句话，兼顾三头——为事情、为对方、为关系
2. **对方视角**:他可能怎么看这件事、在顾虑什么、他的合理之处
3. **事实清单两栏**：我有的证据 | 我的推断（推断当假设带进场，准备好被推翻）
4. **开场白草稿**：30 秒内说完；有分歧的先用对比法（"我不是想X，我是想Y"）排除误解
5. **崩了怎么办**：识别信号（对方开始沉默或攻击）→ 退出内容、修安全感（承认对方合理处 / 重申共同目的）→ 再回正题；实在不行的暂停话术
6. **收尾**：谈成了落到 谁 / 做什么 / 什么时候 / 怎么跟进，别带着感觉散场

## 检查点表

| # | 检查点 | 挑什么毛病 |
|---|---|---|
| 1 | 目标 | 在奔结果，还是在赢争论 / 发泄 / 自保 |
| 2 | 事实 vs 脑补 | 推断穿着事实的衣服 |
| 3 | 安全感 | 哪句会让对方觉得被攻击/被否定——人一防御就听不进任何内容 |
| 4 | 对比法 | 有分歧的表达缺"我不是想X，我是想Y" |
| 5 | 表达顺序 | 结论先行且语气封死（应为：事实 → 推断 → 留余地） |
| 6 | 探询 | 通篇陈述，没有一句问对方的视角 |
| 7 | 行动 | 该收尾的没落到 谁 / 什么 / 何时 |

短消息通常只有 2 / 3 / 5 有戏，七项全列反而稀释重点。

## 场景细则

输入命中"报坏消息 / 顶回 / 指出别人的问题 / 要东西"四类之一、需要范例校准时，Read `ref/scenarios.md`（每类：典型坑 + 坏例→好例 + 场景特有检查点）。

## 输出约束

- 诊断用短列表，每条 = 引用原句 + 毛病 + 一句为什么
- 改写必须给完整可直接粘贴的版本；改动大时给两版（保守改 / 彻底改）
- 不复述理论：输出里绝不出现书名、原则名、章节名，直接给结论

## 示例输出（审稿模式）

输入：`发给 owner：线上世界卡页面挂了，应该是昨天那个 PR 搞的，得马上回退！`（背景：想让 owner 知晓并决策）

> **诊断**
> - "挂了" — 什么现象？报错/白屏/慢？没有事实，对方无法判断严重度
> - "应该是昨天那个 PR 搞的" — 推断穿着事实的衣服，没验证就点名了一个 PR（和一个人）
> - "得马上回退！" — 替对方做了决策还封死了语气；如果推断错了，信用双倍受损
>
> **改写（可直接粘贴）**
> 线上世界卡页面在报错（截图/日志：…），影响范围我还在确认。时间点上跟昨天的 PR #123 吻合，但还没验证是不是它。先同步现象，10 分钟内给结论；如果确认是它，建议回退。
>
> 判断：原稿不能发——两处推断当事实说，且"马上回退"错了没有退路。

## 反模式

- **把直接改成委婉**：用户的问题从来不是太直接，是事实和脑补混着说。改写后读起来像客服（"亲""感恩""麻烦您"式软化剂），就是改砸了。
- **没病硬诊**：干净的草稿直接说"能发"。审稿器说"能发"的时候才积累信用。
- **帮着磨刀**：草稿的目的就是伤人时，不优化它，直接说"这条睡一觉再发"。
- **复述理论**：出现"根据 STATE 原则"这类话就是错的。
- **脑补背景**：不知道发给谁、想要什么结果，先问再改。
