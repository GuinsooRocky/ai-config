# Frontier Reading

给「我现在想读点有价值的东西」这个需求一个十分钟的答案。核心不是捞得多，是**敢淘汰**。

## 何时使用

用户想读深度 AI 内容但不知道读哪篇，或问这类内容该怎么找。默认口径=前沿模型相关的深度内容（安全评测、能力报告、对齐研究、第三方评测）。

用户明说偏向时切换口径：「偏安全」只看 system card 与对齐研究；「偏能力」只看技术报告与基准；「偏行业」放宽到分析类长文。

不该用的边界见 frontmatter。另外：用户手里已经有链接了 → 直接读，不跑本 skill。

## 执行步骤

### 1. 定窗口

默认近 7 天。用户说「最近」按 7 天，说「这个月」按 30 天。窗口越宽越要狠筛，推荐数量不变。

### 2. 捞候选（并行）

```bash
python3 ~/.claude/skills/frontier-reading/scripts/candidates.py --days 7
```

脚本覆盖 HuggingFace 每日论文（按 upvotes 排）+ arXiv cs.CL/cs.AI RSS（按标题关键词过滤）。

脚本**不覆盖**的两类，同一轮里并行手动捞：

- **四家 system card hub**：入口见 `ref/sources.md`。这四家是唯一真做危险能力评估的，出新卡就优先级最高。
- **实验室研究博客 + 第三方评测**：入口同上。

三路并行发，别串行。

### 3. 按四问筛（顺序问，任一不过即淘汰）

1. **有没有别处拿不到的一手数据？** 自跑的评测数字、内部实验、真实部署统计。只转述他人结论的淘汰。
2. **作者有没有承担风险？** 敢写负面结果、敢下可被证伪的判断。通篇好消息的公关稿淘汰。
3. **读完能改变一个判断或动作吗？** 不能就是消费不是投资，淘汰。
4. **48 小时后还成立吗？** 纯事件新闻（融资、人事、发布会）保质期太短，淘汰。

**加分信号**（有就往前排）：披露了自己的失败或退步；给了样本量和评测协议；作者主动加免责声明限定结论强度；被第三方或竞争对手引用。

**直接跳过的形态**：标题是「X 的 N 个启示」「为什么 X 改变一切」；全文没有一个数字；给了 benchmark 分数但不给评测协议；转述别人的报告却不给原文链接。

### 4. 验证再推

**推荐之前必须真读过。** 只看标题和摘要就推等于没做事。至少 WebFetch 拿到正文，确认里面真有第 1 问说的一手数据。

PDF 抓不到文本是常态（WebFetch 对 PDF 经常只拿到二进制）。这时候落盘后用 Read 工具带 `pages` 参数读，别拿摘要糊弄。

### 5. 输出

按「输出约束」给。

## 输出约束

- **最多 3 篇，宁少不多。** 只有 1 篇够格就只给 1 篇。列 10 篇让用户自己挑=把筛选工作退回去了，是本 skill 的核心反模式。
- 每篇必须齐四项：**一句话讲它说了什么** → **为什么值得你读**（锚到具体能改变什么判断）→ **预计读多久** → **链接**。
- 每篇给出至少一个原文里的具体数字或原话，证明真读过。
- 厂商自述的内容必须标一句「这是自评数字」。
- 一篇都不够格时**直说这周没有值得读的**，并说明淘汰了什么、为什么。空窗是合法结论。
- 用户问的是「怎么找」而不是「给我几篇」时：先给篇目，再附筛法，别只给方法论。

**1. An Empirical Study of Harness Design for Coding Agents**（arXiv:2609.20804，43 页，约 40 分钟）

说了什么：4 个模型 × 176 组配置，在 SWE-Bench Verified 和 Terminal-Bench 2.1 上把 harness 的每个旋钮都拧了一遍——5 种上下文管理策略 × 4 档上下文预算。

为什么值得读：它把你凭感觉配的东西变成了有数的结论。三条能直接改动作的：① 上下文管理最强组合是「先规则删除、再 LLM 总结」，不是直接上总结；② planning 对弱模型是提精度、对强模型只是省钱，精度几乎不动——所以给强模型硬塞 planning 是白花钱；③ bash 能力强的模型只给 bash 接口就够，预定义一堆工具反而贵。还有一条负面结果值得看：他们做了「让删掉的内容可恢复」这个机制，结果模型几乎不用，精度零收益。

**2. CAISI's Assessment of Z.ai's GLM-5.3 Cyber Capabilities**（NIST，09-17，简讯，约 5 分钟）

说了什么：美国官方机构自己跑了四个攻防基准（SEC-Bench Pro 183 题、ExploitBench 41 题、ExploitGym 502 题、OSS-Fuzz 297 题）评 GLM-5.3。

为什么值得读：五分钟拿到一张别处没有的对照表——GLM-5.3 在 SEC-Bench Pro 40.4%，美国最佳 90.2%，其他 PRC 模型最佳 27.3%；ExploitGym 上 9.4% vs 美国 44.4%。结论是「迄今网络能力最强的开源权重模型，但明显落后美国前沿约四个月」。这是第三方自跑的数，不是厂商自评。局限他们自己写了：不含未发布的模型。

**半篇：ModularRSI**（arXiv:2609.14857）把 agent harness 拆成五个模块（Agent Loop / Tool Use / Observation Management / Context Management / 完成判定）各自独立演化，2000 个演化任务。跟上面第一篇是同一主题的另一侧。**但我只核到实验规模，没核到具体提升数字**，所以只提一句不正式推——想读的话自己看摘要决定。

## 反模式

1. **列长清单** → 用户要的是一篇，给 20 篇等于没筛。最多 3 篇。
2. **只看标题就推** → 必须 WebFetch 过正文，确认有一手数据。
3. **把新闻当深度** → 融资/人事/发布会消息过不了第 4 问，不进推荐。
4. **把厂商自评当客观测量** → 必须标注。system card 里常有厂商自己写的「别把这些数字当对齐证据」之类限定语，这种限定语本身就是重要信息，要转述给用户。
5. **只推英文大厂** → 中国厂商的技术报告在能力披露上信息密度很高，别因为没有安全章节就整体跳过；反过来也别把它们的报告当 system card 介绍。
6. **串行捞** → 三路来源并行发，别一个个等。
7. **写「目前最新是 X」进任何产物** → 时效性表述一周就错。

## 抓取坑（每次都会遇到）

- `x.ai/safety` 对所有机器请求返 403（带完整浏览器头也挡）。**盯 PDF 直链**（`data.x.ai` / `media.x.ai` 可直取），别盯索引页。
- AWS 的 HTML 一律 403，走 `docs.aws.amazon.com/pdfs/...` 路径。
- HuggingFace 网页版组织页**默认按 trending 排不按时间**，要最新必须走 API（`?sort=lastModified&direction=-1`）。
- 部分厂商 blog 是 JS 壳（抓下来只有导航），只能确认状态码，日期靠交叉核。

来源清单、订阅方式、各家性质：`ref/sources.md`（需要扩展来源或用户问「还能去哪找」时读它）。
