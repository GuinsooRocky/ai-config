# 一、卡片选型：要展示一组内容用哪种卡

卡片的核心判别：**封面比例 + 有无书脊**。1:1 正方形封面、无书脊 = 标准内容卡；3:4 竖向封面 + 侧边色条书脊 + 艺术字标题 = 竖向封面卡。书脊是竖向封面卡最强的视觉签名。

## 1.1 主体内容走哪张卡

| 场景 | 选哪个 | 为什么 | 📍示例 |
|---|---|---|---|
| 首页流 / 分类页 / 搜索 / 文件夹——网格平铺、可点进详情 | **标准内容卡**（卡片积木组合） | 最高频卡，组合积木 `卡片壳→顶部封面→内容区→中部+底部`，承载封面/名/简介/标签/数据/收藏/置顶 | `CardBox.tsx:29` |
| 草稿 / 创建入口 | **草稿卡** | 无收藏/数据，封面下沉渐变蒙层，点击跳创建页 | `DraftCard.tsx:40` |
| 文件夹内（可多选 / 折叠） | **文件夹卡** | 右上换折叠按钮，选中态全卡半透明覆盖 | `FolderCard.tsx:113` |
| 横滑头像列表（非整卡） | **圆头像项** | 只要圆头像 + 名字，不需要整卡信息 | `CharacterIcon.tsx:55` |
| 搜索结果里的用户（非内容主体） | **用户行卡** | 横排 list 行：头像 + 名/统计/bio + 关注按钮 | `SearchUserCard.tsx:44` |

- ✅ 该用标准内容卡：网格里「可点进去的内容主体」标准载体。
- ❌ 别用标准内容卡：竖向封面内容（用竖卡）、纯头像横滑（用圆头像项）、用户卡（用用户行卡）。
- ⚠️ 卡内标签条若走 A/B 灰度，会按 feature flag 分流新旧两版——不是简单替代，是双轨并存（见九、反直觉版本陷阱）。

## 1.2 竖向封面卡——同一组件按 variant 分流

竖向封面卡常用单组件按 `variant` 分多形态，默认竖卡：

| 场景 | 选哪个 variant | 为什么 | 📍示例 |
|---|---|---|---|
| 首页流 / Tab 列表 / 管理弹窗 / 选择弹窗——网格平铺可点进详情 | **竖卡 `vertical`** 🆕 主力 | 书脊 + 3:4 封面 + 题材 chip + 艺术字标题 + 数据 | `WorldCard.tsx:913` |
| 详情页里横向列出关联项 | **长条卡 `longStrip`** | 左封面 + 右文字横卡，PC 多展示简介 + tags | `WorldCard.tsx:731` |
| 创建/编辑流里「已挂载」区块（可切换/删除） | **中长条卡 `mediumStrip`** | 小封面横卡 + 切换/删除按钮 + 权限 gate 态 | `WorldCard.tsx:612` |
| 详情页主视觉大封面 | **详情图卡**（独立文件） | 加粗书脊 + 大封面，点击放大看图 | `world/[id]/WorldCard.tsx:20` |
| 编辑页 PC 左栏实时预览 | **预览卡** | 放大版竖卡，角标纯装饰不可点 | `WorldCardPreviewCard.tsx` |
| 列表里的失效卡 | **失效卡** | 竖卡 + Expired 蒙版，本人态显移除 | `WorldCardExpiredCard.tsx` |

- ✅ 该用竖卡：网格里「可点进去看的竖向封面内容」。
- ❌ 别用竖卡：详情页横向列表（用长条卡）、挂载管理区块（用中长条卡）。

## 1.3 其它内容卡

| 场景 | 选哪个 | 📍示例 |

| 列表加载中（已知形状） | **骨架卡** / 列表末尾占位卡 | — |
| 底栏推荐胶囊 | **底栏推荐胶囊**（胶囊，非卡）🆕 | — |

## 1.4 卡片选型决策树

```
要展示「内容主体」?
  ├ 网格平铺、可点进详情        → 标准内容卡
  ├ 草稿/创建入口              → 草稿卡
  ├ 文件夹内（多选/折叠）       → 文件夹卡
  └ 横滑头像（非整卡）          → 圆头像项

要展示「竖向封面内容」?
  ├ 网格平铺、可点进详情        → 竖卡 variant='vertical'   ← 主力
  ├ 详情页横向列出关联          → 长条卡 variant='longStrip'
  ├ 创建/编辑已挂载区块         → 中长条卡 variant='mediumStrip'
  ├ 详情页主视觉大封面          → 详情图卡
  ├ 编辑器实时预览             → 预览卡
  └ 失效                      → 失效卡

要展示「用户」?                 → 用户行卡（list 行）
选「背景/场景图」?              → 场景卡
列表加载中 / 空?               → 骨架卡 / 占位卡 / 空态卡
底栏推荐?                     → 底栏推荐胶囊
```

# 二、浮层选型：要弹出信息用哪种浮层

六大类浮层共享统一的 z-index 自增机制（见 02-组件 §二、浮层：`useZIndex` 初始 100，后开者每次 +1，写成 inline style——**所以在 `floatingClassName` 写 tailwind `z-*` 无效**）。但锚点 / 遮罩 / 动画 / 移动端形态各不同。

## 2.1 浮层判定流程（决策树）

```
要弹出信息 / 操作 ——

① 要打断用户、强制做决策（确认/表单/选择）?
   ├ 是，且是危险/破坏性（删除等）  → Modal.dangerConfirm（红色警示）
   ├ 是，普通决策/表单             → Modal（命令式 show / Modal.confirm）
   └ 是，但移动端想从底部滑出      → Modal 开 mobileDrawer（退化成 bottom-sheet）

② 不打断，只是反馈「刚发生了什么」（保存成功/复制/报错）?
   → Toast（移动端可套上滑关组件）

③ 侧边/底部滑入的长内容、需保留主页面上下文?
   → Drawer（侧栏面板 / bottom-sheet / 侧滑手势关闭）

④ 锚定某个触发元素旁的轻量补充?
   ├ 纯 hover 单条引导文字、要一次性/定时/埋点  → Tooltip
   ├ 要带可点元素的菜单/字段说明、要箭头指向源  → Popover
   └ 引导气泡要用户手动关、不自动消失           → 手动关闭气泡（ClickClose 变体）

⑤ 操作列表浮层（无遮罩、点项即执行）?
   ├ 锚在「⋮/更多」按钮上            → 更多菜单按钮（Popover 封装）
   ├ 右键/长按某条目唤起            → 上下文菜单（坐标定位+portal）
   ├ 字段旁 ⓘ 纯说明               → 字段说明气泡（FieldInfoPopover）
   └ 按坐标精确定位的通用菜单        → Menu（取最新版）

⑥ 多步引导教学（轮播+图+Back/Next/Done）?  → 多步引导弹窗
⑦ 全屏图集浏览（铺黑、横滑、手势）?         → 图片预览弹窗
```

## 2.2 Modal vs Drawer vs Popover vs Tooltip vs Toast vs 菜单（横向决策表）

| 类别 | 锚点 | 遮罩 | 何时用（✅） | 何时别用（❌） |
|---|---|---|---|---|
| **Modal 弹窗** | 屏幕居中 | 有半透明遮罩 | 需明确决策（删除/年龄/登录）、承载表单、聚焦中等内容 | 纯信息反馈（用 Toast）、依附按钮的轻提示（用 Popover/Tooltip） |
| **Drawer 抽屉** | 屏幕一边 | 有半透明遮罩 | 侧栏面板、移动端底部长内容/操作面板、需侧滑手势关 | 强决策小弹窗（用 Modal.confirm）、轻提示（用 Toast） |
| **Popover 气泡** | 触发元素 | 无 | 字段 ⓘ 说明、「更多」下拉、要箭头指向源的补充信息（可含可点元素） | 纯 hover 单行文字（Tooltip 更轻）、需遮罩的决策（Modal） |
| **Tooltip 提示** | 触发元素 | 无 | 新功能一次性引导（onceKey 只弹一次）、定时消失轻提示、要曝光埋点 | 多内容/可点菜单（用 Popover） |
| **Toast 轻提示** | 顶部居中/锚点 | 无（`pointer-events-none`） | 保存成功/失败、复制成功、网络错误、一次性 loading | 需用户决策（Modal）、依附按钮的持续说明（Popover） |
| **菜单/上下文菜单** | 触发元素/坐标 | 无 | 右键/「更多」按钮触发的操作列表 | — |

**一句话选型**：要打断必须决策 → Modal；侧/底滑出长内容 → Drawer；点/悬浮触发的轻补充 → Popover/Tooltip；操作结果反馈不打断 → Toast；右键/「更多」操作列表 → 菜单。

## 2.3 关键细分

- **Modal 还是 Drawer？** 同一个 Modal 在移动端可传 `mobileDrawer` 退化成底部 bottom-sheet，所以「PC 居中弹窗、移动想从底滑」用一个 Modal + `mobileDrawer` 即可，不必拆两个组件。移动端抽屉本身就是对 Drawer 的封装。
- **Popover 还是 Tooltip？** Tooltip 是「基于 Popover 封装的一次性新功能引导气泡」（带 onceKey/duration/suppressed/曝光埋点）。要这些能力 → Tooltip；要放可点元素/菜单/字段说明 → 直接用 Popover。
- **删除二确为什么必须 dangerConfirm？** `Modal.dangerConfirm`/`asyncDangerConfirm` 是红色警示版，破坏性操作（如立即真删无 Undo）走它。普通确认用 `Modal.confirm`。
- **彩色强调气泡** → 强调色气泡（红/绿强调色 + 箭头），用于错误/新功能引导这类要抓注意力的；中性补充用 Popover 的中性底色。

## 2.4 域内浮层实例（都基于 Modal 派生）

| 场景 | 关键 | 📍示例 |
|---|---|---|
| 删除二确 | 走 `Modal.dangerConfirm`，红警示，立即真删 | `showDeleteNoteConfirm` |
| 跨分类移动二确 | Modal width=600，双按钮 Cancel/Move | `MoveNoteConfirmDialog` |

# 三、按钮选型：该用哪个变体 / 何时禁用 loading

## 3.1 Button 的设计哲学（必读）

Button **只管配色 + 通用过渡/禁用**，**几何（圆角/padding/尺寸）由调用方传 className**。典型调用要自补 `rounded-full px-6 py-3`。见 02-组件 §一、控件。

## 3.2 主次 / 危险 / 灰色——选哪个 color

| 场景 | color | 为什么 |
|---|---|---|
| 最重要的主行动（确认/保存/开始/CTA） | **`primary`（默认）** | 主题主色实色填充，最高视觉权重 |
| 次要但仍需强调 | `secondary` / `new-secondary` | 次级主题色实色填充 |
| 取消 / 次要操作 | `gray` | 浅灰底黑字（亮）/ 深灰底浅字（暗） |
| 深色背景上的浅色按钮 | `tertiary` | 白底黑字 / 半透明白蒙层底白字 |
| 危险/破坏性（删除）的**确认弹窗** | 不是 Button 变体——用 `Modal.dangerConfirm`（红警示）；菜单里的危险项用红字 + 红色 hover 底 |

- ✅ 主操作永远只有一颗 `primary`，配一颗 `gray`（取消）。
- ❌ 一个弹窗里别放两颗 `primary`——主次不分。

## 3.3 图标方块 / 幽灵按钮 / 业务态按钮——别用 Button

| 场景 | 用哪个 | 📍示例 |
|---|---|---|
| 关注 / 已关注 | **关注按钮**（带已关注弱化灰态） | `FollowButton.tsx:90` |
| 详情页核心互动（点赞/收藏/记忆/分享一组方块） | **动作按钮组** | `CharacterActionButtons` |
| 需要动画反馈的收藏 | **带动画收藏图标** | `FavoriteIconWithAnim` |
| 营销落地页 CTA | **落地页按钮**（独立色系） | `LinkButton` |
| 卡片操作的「图标方块」 | 各卡片自带（如圆形半透明底图标按钮） | — |

- ❌ 别用 Button 做：图标方块、带边框幽灵按钮、关注/点赞这类业务态按钮——它只管实色填充配色。

## 3.4 何时禁用 / loading

| 状态 | 表现 |
|---|---|
| **disabled** | Button 内置：`cursor-default` + 半透明底 + 弱化字色 |
| **loading** | Button **无内置 loading 态**，业务层自行包 spinner（用圆环 Loading） |

**何时该禁用**：
- 表单未填必填项 / 未改动（`isDirty=false`） → 禁用主按钮。
- 提交进行中（`isSaving`）→ 禁用 + 上 loading（如 `disabled: !isDirty || isSaving`）。
- ✅ loading 期间一定要禁用，防重复提交。
- ❌ 别用 disabled 表达「权限不足」却不给解释——那种情况给 toast 或 gate tag（如权限门 tag）。

# 四、状态信息：用 tag / badge / 红点 / 星级 哪个

核心区分：**Tag = 这条内容属于哪类（可点筛选）；Badge = 这个对象的身份/状态（不可点）；红点 = 有/无新内容（布尔）；星级 = 1-5 级程度。** 见 02-组件 §四、标签徽章。

## 4.1 选型决策表

| 你要表达 | 用什么 | 为什么不用别的 | 📍示例 |
|---|---|---|---|
| 这条内容属于哪一类（可点筛选） | **Tag/Pill** | 数据驱动的分类标签，可点选切换 | `Tag/TagV2.tsx` |
| 用户可增删的关键词 | **可删 Chip** | 输入产物，每个带 × 可删，非预设 | `KeywordChipInput` |
| 互斥单选的视图过滤（All/Unfinished） | **筛选 Chip** | 固定 2 选项 + 计数，非数据驱动分类 | `NotesFilterChips` |
| 对象的付费等级 / 草稿状态 | **Badge** | 表达身份，不可点 | `ProTag`/`UltraBadge`/`DraftBadge`/权限门 tag |
| 对象正在审核/被限/被封 | **审核 Badge** | 合规状态，颜色语义化（红禁/黄限/绿过/粉改级） | `AuditResultBadge` |
| 有没有未读/新内容（布尔） | **红点** | 只表达有/无，不带数量精度 | 全局红点驱动 |
| 一个数值的剩余量/超限警告 | **计数指示器** | 三阶段色（蓝/黄/红）随阈值 | `CharCountIndicator` |
| 1-5 级程度选择 | **星级** | 可点 5 星 + hint 文案 | `PriorityLevelStars` |

## 4.2 Tag 的具体选型

| 场景 | 用哪个 | 关键 |
|---|---|---|
| 可点筛选栏 | 筛选 Tag 的 `lg` 档（30px 高） | 选中=主题色 20% 底 + 主题色字 |
| 卡片封面下方的标签条（展示型，自动溢出 +N） | 展示型标签盒 🆕 | 把前缀状态徽（target/scene/world/分级/event）+ 普通 tag 放一行 |
| 卡片小角标 | Tag 的 `sm` 档（16px 高，10px 字） | 卡片密集场景 |
| 活动标签 | Tag 的 `isEvent` 分支（渐变字/渐变底） | 不用旧版独立 EventTag |

- ✅ 可点筛选用筛选 Tag；卡片角标用展示型标签盒。
- ❌ 别新增 `GradientTag`/`EventTag`/`TargetTag`/`AlbumTag` 这类已被统一 Tag 取代的旧家族（仅内部历史引用还在，见九、反直觉版本陷阱）。

## 4.3 Badge 横向对比

| Badge | 底 | 字色 | 语义 | 📍示例 |
|---|---|---|---|---|
| **Pro 徽** | 金黄渐变 | 黑 | Pro 会员 | `ProTag.tsx` |
| **Ultra 徽** | 彩虹渐变 | 紫 | Ultra 会员 | `UltraBadge.tsx` |
| **草稿徽** | 半透明中性 + 模糊 | 弱化紫 | 草稿未发布 | `DraftBadge.tsx` |
| **权限门 tag** | 透明描边 | 主题色 | 需高等级才能用 | `VipGateTag.tsx` |

- ⚠️ **Pro/Ultra/草稿徽是共用基底契约**：被多处调用，基础样式不能改，单点对齐用调用处 className override（历史踩坑：改基底导致多处变形，见八、共用组件改动安全边界）。

## 4.4 红点为什么不能当数量用

红点驱动通常是纯逻辑（拉计数 + 写 store，`return null` 无 DOM）。红点只表达「有/无」——要展示精确数量用计数 badge（如数字徽标 `>99` 时变宽），不要用红点。

# 五、加载与反馈：骨架 vs spinner / Toast vs Banner / 空态

详见 02-组件 §五、反馈动效。

## 5.1 加载：用骨架还是 spinner

| 场景 | 选哪个 | 为什么 |
|---|---|---|
| 列表/卡片首屏拉数据，**已知布局形状** | **骨架屏** | 占位即未来内容形状，无跳变，体感更快 |
| 操作型阻塞（提交中/跳转中/整页等待） | **全局遮罩 spinner**（最高层级） | 盖住整页 + 半透明遮罩，禁误操作 |
| 局部容器/弹窗内拉数据，**布局未知** | **圆环 spinner**（Loading） | 轻量居中，无需画骨架 |
| 有明确百分比（上传/导入/克隆） | **环形进度** | 圆环 + 中心 % 数字 |
| 等 AI 回消息（气泡内） | **打字点** | 聊天专属「对方正在输入」 |
| AI 文本逐词吐出 | **打字机** | 按分词逐段揭示 |
| 滚动列表加载下一页 | **触底哨兵 + spinner** | IntersectionObserver 触底自动拉 |
| loading/空/有数据三态切换 | **三态编排器**（传 fallback） | 让列表三态逻辑统一 |

- ✅ 已知形状用骨架（每种卡自己画一份，几何贴合真实卡）。
- ❌ 局部等待别用全局遮罩 spinner（会黑全屏）；纯静态文本别套打字机；打字点只用于聊天气泡，别当通用 loading。
- ⚠️ 骨架可纯静态灰块（靠形状占位）或叠 `animate-pulse` 脉动，按系统约定统一。

## 5.2 反馈：用 Toast 还是 Banner

| 场景 | 选哪个 | 为什么 |
|---|---|---|
| 一次性、自动消失的操作结果反馈 | **Toast**（移动端套上滑关组件） | 短促、不占版面、不阻断 |
| 需用户继续看见 + 带操作按钮的状态提示 | **Banner** | 常驻内容流，带 CTA（Manage/Clear/折叠） |

**Banner 三种各管什么**：
- 结果型 Banner（如导入完成 + 去管理入口）：带 CTA，比 Toast 重，常驻 + 带关闭。
- 低存在感 Banner（如「草稿已恢复」+ Clear 撤销）：用户一改字段自动消失。
- 结构化 Banner（如板块标题 + 字数三阶变色预警 + 移动端折叠）：标题/预警/折叠三合一。

- ✅ Toast 给「做完了/出错了」；Banner 给「这状态要你看见并可能操作」。
- ❌ Toast 别拿来要决策（用 Modal）或做按钮持续说明（用 Popover）。

## 5.3 空态怎么摆

| 场景 | 选哪个 | 区别 |
|---|---|---|
| 各 Tab 无内容（自有内容列表） | **空态卡** | 图标 + 文案 + **「+新建」按钮**（引导在此创建） |
| 通用「这里没内容，去逛逛」 | **发现型空态** | 图标 + 双行说明 + 引导按钮（引导去别处发现 trending） |
| 编辑器初始无内容 | **编辑器空态** | 渐变大 hero + Starter 入口卡（仪式感重） |
| 路由级 404 | **404 页** | 整页主题插画 + 单一回首页 CTA |

- ✅ 「空 + 引导创建」用空态卡；「空 + 引导去发现」用发现型空态。
- ❌ 纯展示型空态（无创建动作）别套带新建按钮的空态卡。

# 六、表单输入控件选型

表单常有多套并行血统，新场景**优先卡片化字段壳 `FieldShell` 体系**（最新卡片化分区）。详见 02-组件 §一、控件 与 03-布局模式 §选择模式。

## 6.1 输入框选型

| 场景 | 选哪个 | 样式特征 |
|---|---|---|
| 搜索/筛选行内输入 | 药丸形带边框 `Input` | `rounded-3xl border bg-white`，focus 切主题色边 |
| 卡片化表单字段 | 扁平暗灰底输入 | `rounded-[12px] border-0` + 半透明灰底（无边框） |
| 老一代通用整包字段 | 全局 CSS 类驱动的 `BaseInput` | react-hook-form 整包 |

- ✅ 新页面用扁平暗灰底（字段壳内）。
- ❌ 新页面别用老一代整包字段（已被字段壳取代）。

## 6.2 多行文本域（四套实现）

| 场景 | 选哪个 |
|---|---|
| 受控截断 + 内置计数（基础原子） | `Textarea`（基础版） |
| 行高换算自适应 | `TextareaAutoLine`（minRows/maxRows） |
| 聊天输入框等随内容增高 | `AutoTextarea`（隐藏镜像测高，含长按全选） |
| 成熟库式行数钳制 | `AutosizeTextarea` |

## 6.3 选择/单选/复选/滑块

| 场景 | 选哪个 | 为什么 |
|---|---|---|
| 选项多/需主题配色/可搜索 | **重型 Select**（多套配色主题，移动端转抽屉） | 重型选择器 |
| 轻量 popover 小下拉（排序/筛选维度） | **轻量下拉**（基于 Popover）🆕 | 新场景首选 |
| 「更多操作」式菜单（含可点链接项） | **菜单式下拉**（hover 高亮强） | 字号更小 |
| 标准单选 | **圆点单选**（取现役主流版） | ⚠️ 反直觉：旧版仍 canonical（见九） |
| 「分段选择器」外观的单选 | **胶囊单选**（整 label 变胶囊） | 局部新版 |
| 多选 | **Checkbox**（circle/square + primary/secondary） | — |
| 少量互斥选项（性别/触发模式） | **chips 按钮组**（非下拉） | `rounded-[25px]` chip，选中=主题色 20% |
| 音量条（无 thumb 纯填充） | Slider `volume` variant | 设计要求无 thumb |
| 其它进度型滑块 | Slider `default` variant | — |

## 6.4 字段壳 / 字段四件套

| 场景 | 选哪个 |
|---|---|
| 新页面表单字段（要标题+必填+info+helper+error+计数完整 anatomy、PC/移动卡片差异） | **字段壳 `FieldShell` + Card** 🆕 首选 |
| 简单单字段 | 输入原子（`Input` 等） |
| 自定义组合标签/描述/错误 | 字段四件套（`FieldTitle`/`FieldDescription`/`ErrorMessage`/`Label`，各取现役版） |

## 6.5 表单校验展示（统一约定）

- **错误态输入框**：不用红警告色描边，而是「半透明红框 + 红底蒙层」。
- **错误提示两种风格**：① 红底胶囊（卡片表单主流）；② 纯红字（基础原子）。
- **必填标识**：一律**主题色 `*`**，**不是红色**。
- **校验时机**：失焦校验（`onBlur` 设 error），输入达标即时消错（`onChange` 清 error）。

## 6.6 图片上传选型

| 场景 | 选哪个 |
|---|---|
| 比例可变的矩形封面 | **矩形封面上传**（四态机：empty/loading/uploaded/error，按场景比例撑高）🆕 |
| 固定圆形头像 | **圆形头像上传**（圆形预览 + 按钮） |
| 角色表单专用复合头像 | **复合头像输入**（集成裁剪/动图） |

# 七、移动 vs PC 布局取舍 / 何时做 .pc.mobile 拆分

详见 03-布局模式 §响应式/端拆分。

## 7.1 全站布局让位机制

主骨架可不用 grid/flex 分栏，而是**用左右内边距给 `fixed` 侧栏让位**（padding 随侧栏状态在断点切换）。典型尺寸：

| 元素 | 尺寸 |
|---|---|
| 左侧栏展开 | `232px`（`ps-[232px]`） |
| 左侧栏 mini 态 | `69px`（`ps-[69px]`） |
| 中间列表展开 | `370px`（`ps-[370px]`） |
| 右侧栏 | `300px`（`pe-[300px]`） |
| main 底部安全区 | `pb-[80px]`（给移动底栏让位） |

- 所有 padding 用 `ps-`/`pe-`（logical，自动 RTL 适配）。

## 7.2 断点选型

| 断点 | 值 | 何时用 |
|---|---|---|
| `lg` | `1024px` | 普通页侧栏显隐分界、卡片 hover 阴影、汉堡按钮 `lg:hidden` |
| 自定义大断点 🆕 | `1280px` | **仅特定双侧栏布局分界**（如聊天详情） |
| `sm` | `640px` | 多数 PC/移动样式分叉（padding/字号/间距） |
| `md` | `768px` | 移动判定分界、卡片背景 PC/移动切换 |

- ⚠️ 系统可能**覆盖 Tailwind 默认断点值**（如 `xs=420`），非标准，落地前查 `tailwind.config.js`。
- 一处特殊双侧栏用自定义大断点，其它页统一用 `lg`/`sm`。

## 7.3 何时做 `.pc.tsx` / `.mobile.tsx` 文件级拆分

| 拆 / 不拆 | 判据 | 例 |
|---|---|---|
| ✅ **拆文件** | PC 与移动**交互模型本质不同**（不是样式差异） | 编辑框架（PC 双栏+拖拽+框选+右键 / mobile 单列+整页跳转）、条目卡（PC 瘦行+双击改名 / mobile 胖卡）、筛选 chips（PC 带管理齿轮 / mobile 无） |
| ❌ **不拆** | 仅 light/dark、间距、字号差异 | 编辑器头/草稿徽/关键词输入/书脊——单文件内 `dark:`/`md:` 断点解决 |

- ✅ 拆文件：交互范式根本不同（拖拽 vs 跳转、双栏 vs 单列、瘦行 vs 胖卡）。
- ❌ 别拆文件：只是颜色/间距/字号差——用 `dark:` + `md:` 断点。

## 7.4 PC/移动组件形态对照（落地常查）

| 组件 | PC | 移动 |
|---|---|---|
| 左侧栏 | 桌面侧栏（fixed 常驻 + padding 让位） | 移动侧栏（Drawer 浮层） |
| 顶栏 | 完整顶栏（汉堡区 `lg:hidden`） | 同组件移动分支（汉堡 + 移动开关） |
| 底栏 | 无 | 移动底栏（如 App 下载横幅）🆕 |
| Modal | 居中卡片 | 传 `mobileDrawer` → 底部 bottom-sheet |
| Tooltip | hover 触发 | tap 触发 |
| 场景卡 | 横卡 | 抽屉竖卡 |
| Select（可搜索） | 下拉 | 底部抽屉 |
| 条目卡 | 瘦行（双击改名） | 胖卡（头像+关键词+描述两行） |

## 7.5 各路由组 chrome 差异（决定页面有没有外壳）

| 路由组 | chrome | 何时落在这 |
|---|---|---|
| 主仪表盘组 | 完整（横幅+侧栏+顶栏+main+移动底栏） | 首页/列表/个人/定价/商店等核心页 |
| 自带布局组 | 无外壳（透传 children） | 详情/活动/支付（自带布局） |
| 文章组 | 无自有 layout | FAQ/隐私/条款纯文章页 |
| webview 组 | 透明全屏占位 | App 内 webview 浮层 |

# 八、🌗 暗亮主题落地铁律（跨章共性）

详见 01-基础 §令牌+主题。

- **主题色永远成对写**：light 用主主题色（如紫），dark 用对应暗色（如粉），写成 `text-light3-primary dark:text-dark3-primary`。
- **次级色规律**：亮/暗各有对应次级色对，成对取。
- **页面背景**：`bg-light3-bg` / `dark:bg-dark3-bg`，由 body 透出。
- **填充蒙层惯例**：亮底 `bg-black/4`、暗底 `bg-white/4`。
- **少数「反 swap」不是简单 `dark:` 反色**（要留意）：
  - 权限门 tag：light=紫 / dark=黄，为在暗色区块醒目。
  - 红点：亮红 / 暗用品牌绿（暗色下红点改绿更醒目）。
  - 部分 Banner 按钮：亮蓝白字 / 暗绿黑字。
  - 部分 TabBar inactive 态：各自兜对应对比度，非线性深浅切。
- **不随主题切的固定色**（硬编码 hex，别加 `dark:`）：
  - Toast 底色/边色（浅底深字，两模式一致）。
  - 彩虹渐变徽、webp 背景图、动效装饰色（如雪色）。

# 九、共用组件改动的安全边界（落地避坑）

详见 01-基础 与各组件章。

- **改共用组件要同时顾两条轴**：PC/mobile（z-index/布局）+ dark/light（颜色/背景）。
- **基底契约不能改**：Pro/Ultra/草稿徽被多处调用，单点对齐用调用处 `className` override，禁止改基础样式（历史踩坑：改基底导致多处变形）。
- **z-index 别在 floatingClassName 写 tailwind `z-*`**：浮层走 inline style 自增层级，class 会被覆盖无效；要调层级靠打开顺序。
- **本地 dev 静态图会裂**：`/static/` public 图用 inline `backgroundImage` 别用 next/image（customLoader 在本地够不着 localhost）。

# 十、🆕 反直觉版本陷阱（写规范/落地必读）

**不是所有 V2/V3 都比 V1 新且更主流**。机械「取最新版」会写错/用错。按精确 import 路径计数为准（数字仅示例量级）：

| 组件族 | canonical（现役主流） | 陷阱 |
|---|---|---|
| **基础 Modal** | **V1**（大量 import） | ModalV2 近乎弃用；命名带 `*ModalV2` 的多是业务弹窗，与基础组件无关 |
| **Radio** | **V1**（最多） | RadioV3（最新）/RadioV2 用量都小，未取代 V1 |
| **ErrorMessage** | **V1**（多） | V2 仅少量 |
| **Switch** | **Switch2** 🆕 真新版 | V1 仅少量旧调用 |
| **Tooltip** | **TooltipV2** 🆕 | 但 V1 仍未弃用，两版并存用量相当 |
| **Dropdown** | **DropdownV2**（现役） | V1 业务 0 引用（仅 stories）=已弃用 |
| **改版 V2 族**（Tag/TagBox/TagFilter/TagList 的 V2） | **V2 为 revamp 主流** | 来自 A/B 灰度——V1 和 V2 是**双轨并存**（V1 在对照组运行），不是简单替代 |

**图标同理**：「改动新 ≠ 采纳广」。如某图标的最新描边版仅 1 处用，按使用量旧实心版仍 canonical。

**图标语义易混（别当同图标的多版本）**：
- 「更多」(三点) vs 「汉堡菜单」
- 「收藏」(星) vs 「点赞」(拇指/心)
- 「删除」(垃圾桶) vs 「移除」(减号)
- 「基础锁」 vs 「会员付费专用锁」(带光/星)
- ⚠️ 同功能不同域可能取不同图标变体（如某域删除用描边垃圾桶、主表用实心垃圾桶），落地照各域实际。
