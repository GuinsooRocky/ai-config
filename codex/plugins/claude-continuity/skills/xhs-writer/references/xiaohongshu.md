# 小红书 9 图帖 · 生成与修改

khazix-writer 的小红书产出线。触发：「根据 X 出小红书」「做成小红书帖」「改小红书」。

## 这条线在做什么

把一篇已有的笔记 / idea / 文档，做成一条小红书 9 宫格图文帖：9 张卡片图 + 帖子标题 + 正文。

重心是**陪用户改**，不是无中生有 —— 灵感、观点、踩过的坑由用户出，skill 负责成形和迭代。默认用户已经有原料；没有就先问，别自己编。

## 默认视觉风格 · 黑白发布版

默认用 `references/xiaohongshu_template.html` 的黑白发布风格：

- 黑字、大留白、轻微米白底、细线框，整体像一份认真整理过的个人笔记。
- 不使用红色渐变封面，不使用高饱和营销色，不用强按钮感 CTA。
- 卡片是 `1080×1350` 的 4:5，小红书 feed 流更稳；除非用户明确要 3:4，再改回 `1080×1440`。
- 封面靠一句判断拉人，不靠色块刺激。标题要像作者自己想明白的一句话，不像课程海报。
- 内容卡少用「凭什么证明 / 常见坑」这种模板味标签，优先用「我后来发现 / 真正卡住的是 / 这一步会劝退很多人」这种人话判断。

这条线尤其适合「能力展示 / 工作流陪跑 / 经验沉淀」类内容。目标不是显得会做设计，而是让读者感觉：这个人真的思考过，也真的能陪我把事情跑通。

## 四步流程

### 第 1 步 · 选角度（三种骨架）

三种常用骨架：

- **科普向**：把一套知识讲清楚。封面 → 概念 → 干货卡 ×5~6 → 总结/规则 → 引流。收藏率高，每点偏浅。
- **单点向**：只讲一个最反直觉的点。封面 → 痛点 → 这个点 → 怎么用 → 反例 → 引流。最适合小红书，钩子强。
- **故事向**：用「我踩了个坑」串起来。封面 → 起因 → 经过 → 转折 → 收获 → 引流。人味最足。

**⚡ 用 Workflow 三路并行（推荐）**：用户给素材后不用先选角度——用 Workflow tool 触发 `xhs-writer` workflow，三路同时跑，返回对比报告让用户选最好那路，再进入第 2 步迭代。

```
触发：用户说「出小红书」「三路都出」且有素材
args: { material: "<素材全文>", topic: "<可选>" }
```

用户明确说只要某一路（「就出单点向」）时，跳过 workflow 直接进第 2 步。

### 第 2 步 · 出 HTML

复制 `references/xiaohongshu_template.html` 到 `~/Desktop/PRD/小红书/MM.DD-<简短标题>.html`，填三块：

1. 帖子标题候选（4 条，发布时填小红书标题栏）
2. 9 张卡片（封面 + 7 内容 + 引流）
3. 正文（贴帖子下方的文字 + hashtag）

**生成时边写边套去 AI 味**（见下文「去 AI 味」节），不要先写脏再洗。

### 第 3 步 · 迭代修改（这条线的核心）

出完第一版，用户会逐条提改动。常见招式：

| 用户说 | 怎么改 |
|---|---|
| 换个角度 / 钩子不行 | 回第 1 步重选骨架，或只换封面大字 |
| 内容太少 / 太简短 | **回原始素材翻料**，把之前压掉的细节加回卡片；或给每张卡补「⚠️ 常见坑」框 |
| 太 AI 味了 | 走「去 AI 味」节，按禁区清单逐条扫 |
| 加标题 / 标题不对 | 改标题候选区；记住封面大字 ≠ 帖子标题 |
| 这页太空 / 太挤 | 调卡片内容密度，每张卡 4 个区块左右算匀 |

每轮改完只报改了什么，自动推进，别问「要不要继续」。

### 第 4 步 · 导出发布

模板自带「导出 9 图」按钮：点一次，9 张图打包成 1 个 zip 下载，每张 `1080×1350`（小红书 4:5 竖图）、直角无圆角。用户解压即可发。

## 9 图通用结构

- 图 1 = 封面：大字钩子 + 副标 + 一行可信背书小字
- 图 2~8 = 内容卡，每张 **2~3 种元素**，按下面三种 variant 轮换：
  - **A · 极简骨架**：`badge + h2 + p`。最常用，全帖至少 3~4 张
  - **B · 笔记向**：极简 + `⚠️ .box` 注解框（只在真有警示 / 反直觉点用），全帖建议 1~2 张
  - **C · 大字卡**：`.big-card` 整页一句话，用于转折 / 金句 / 收尾铺垫，全帖建议 1~2 张
- 图 9 = 引流：收尾 + 一个互动钩子（邀评论）
- 干货 : 引流 ≈ 3 : 1，别太用力推
- **反 AI 模板腔**：禁止 eyebrow + h2 双标题；禁止 p1 + p2 + box 三段同义复读；元素堆 4 种以上就回退到 variant A

## 钩子规范

- 钩子用**生活场景 / 痛点**，不堆术语（「代码三个月后改不动」优于「架构耦合度过高」）
- 封面大字拉人进来，副标筛共鸣
- 标题 4 条候选，痛点向放第一条标「推荐」

## 招式库 · 可复用句式

需要现成句式 / 钩子模板 / 范式参考 → 查 `references/xiaohongshu_style_moves.md`。

里面按招式编号收录（翻转句式、自嘲开局、降级期待收尾等），每条带「模板 + 示例 + 用在哪」+ 与三种骨架的适配表。出帖前扫一眼，按需挑用。新范式按来源累加。

## 配图（小黑式手绘）

要给帖子配手绘概念图（不是 HTML 卡，是 AI 出的怪诞插画）→ 查 `references/illustration.md`。

那条线只产出 **shot list + 可直接粘的 prompt**，用户拿去**自己的出图网站**跑（本机无出图工具，别调 image_gen）。挑认知锚点配 4-8 张，小黑承担核心动作。画幅：整张卡 4:5、嵌卡当横插 16:9。触发：「配图」「出配图 prompt」「画个小黑」「这篇哪里值得配图」。

## 去 AI 味（小红书适配）

小红书帖也走 `SKILL.md` 的「第三步·绝对禁区 + 第四步·L1」，但有一处适配：

- **通用照搬**：禁破折号「——」、句中冒号改逗号、双引号用「」、禁「说白了 / 本质上 / 换句话说 / 意味着」等 AI 高频词、工具名写具体。
- **小红书特例**：卡片里的块标签冒号（「例：」「凭什么证明：」「⚠️ 常见坑：」）**保留** —— 那是卡片笔记格式，不是长文报告腔。
- 卡兹克专属口癖（赤鸡、不是哥们、固定尾部三连）**不要**套到小红书 —— 小红书是用户自己的博主人设，不是卡兹克。
- **能力展示帖特例**：少说「一篇讲清楚 / 保姆级教程 / 收藏备用 / 直接抄作业」。这种词流量味重，也显得廉价。改成「我一般先看 / 我会先帮你拆 / 这一步最容易卡住 / 你可以把你的场景丢出来」。
- **陪跑视角**：如果用户的目标是获客，正文和尾页要把读者带回自己的场景，让他愿意留言职业、任务、卡点；不要只输出知识，不然读者收藏完就走。

## 工作阶段（采集 → 框架 → 文案，别抢跑）

用户写帖子分 3 阶段，AI 不要混：

1. **素材采集**：用户口述经历 / 项目 / 感受 — AI 只**结构化记 + 确认语音转写歧义 + 给大致框架方向**。不主动给钩子文案、金句、封面、9 图分镜
   - **细节追问的克制**：用户标"不重要 / 忘了 / 没必要"的细节直接划掉，不再问。一轮最多 2-3 个真正影响成稿的待确认。用户原话「你没必要非得对每一个都那么认真，因为我觉得这个帖子少了 1 无所谓」
2. **框架对齐**：用户确认 A/B 分类轴、点名策略等关键决策后再走下一步
3. **文案输出**：用户明确说"出钩子 / 出文案 / 排分镜"才进入

用户原话「你先不要玩命的给我输出钩子呀什么要内容什么的」。

## 硬规矩

- 落点固定 `~/Desktop/PRD/小红书/`，文件名 `MM.DD-<简短标题>.html`
- 只产出 HTML，不出 `.md`
- 写完只报绝对路径，不提「拖入有道云笔记」
- 搜来的数据只用来校准观点 / 调风格，不直接进帖子
  - **观点站得住就不要提**（避免水分）；只在用户观点**明显错误 / 误导读者**时，引用 1-2 篇文章给用户看让他自己决定改不改
  - 内部参考想留，开「Claude 内部参考」区块、明确标"不进帖子"
  - **「信源清单」这种 SEO 痕迹强的 section 不要写进帖子草稿**（300 粉技术垂直粉信任的是用户的判断，不是数据；数据多了像 SEO 文）
- **干货 : 引流 = 3:1**：每 4 篇里只放 1 篇带强引流钩子（私信/加群/导流），其余 3 篇纯干货建信任。引流贴占比过高会被平台限流 + 掉粉；早期纯涨粉阶段引流贴可再压低或不发
