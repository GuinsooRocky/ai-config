# 多源调研模式细则

> 本文件只在触发调研模式时加载。单篇分析不要读它。

## 本模式的增量与不适用场景

**北极星：个人认知与知识丰富度的增量**——教学层和大牛视角是主菜；项目转化（裁决落盘）是副产品，不是每篇的义务。

相比"主对话直接读几篇聊一聊"，本模式只有四项真增量——不沾这四项就别启动：

1. **正文可达性**：风控平台（微信/小红书/B站）与 PDF 的正文，裸聊拿不到
2. **事故红线固化**：≤2 并发 + 内容特征校验，写在编排里而不是靠记性
3. **带引源的真实反方**：每条反对意见有 URL + 原文引句，不是模型白聊
4. **批量不爆上下文**：N 篇全文留在子 agent，主对话只收卡片

镜面规则：**单篇英文公开网页 + 随便聊聊 → 直接主对话聊，不要启动本模式。**

## Intake 细则

| 来源 | 通道 | 引用可达等级 |
|---|---|---|
| 微信/小红书/X/YouTube/B站 | `sf-reader-all`（红线见 SKILL.md Step 1） | 微信/X/视频=仅提及；**小红书=无** |
| 通用网页 / RSS | 首选 `sf-reader-all` 落 unified_inbox.json；跑完按内容特征校验不过真正文 → WebFetch 兜底（5 个风控平台仍禁止），兜底正文存 `~/Desktop/archives/技术总结/_raw/<slug>.md` | 仅提及 |
| arxiv / 本地 PDF | 内联下载到 `~/Desktop/archives/技术总结/_raw/`（内联抓取补口） | full |
| 播客 / 视频 | video skill 转写 + **必须保留简介 description**（引用的真实载体） | 仅提及 |

- 小红书显式跳过引用提取（实测正文连出链都没有），输出"本源无引用原料"，不算失败
- 微信正文 URL 先过图床黑名单（mmbiz.qpic.cn / wsrv.nl / sinaimg）再提取提及
- **视频转写降级**：转写通道不可达（工具坏/风控/无字幕）→ 修复尝试限 1 次即放弃，工具修复另开任务；时长 ≤3 分钟且简介已是成段论点陈述的也可直接免转写。两种情况精读卡一律标「仅简介未转写」，该源主张只作二手线索、不作 established 主张直接采信，并照常计入未覆盖清单

## 精读工人（每篇一个，Agent 工具并行 spawn）

**薄源例外**：实际抓到的 content 正文 <500 字（短推文、仅有简介的视频等）**不 spawn**——工人唯一价值是隔离全文，薄源无全文可隔离；主对话直接产同字段薄卡并标「薄源」，《提及/引用作品清单》字段必须保留（首跑实证：72 字源也牵出了值得追的引用链）。前提：已按红线校验确认正文本来就这么短而非抓取失败残片；视频简介薄 ≠ 豁免转写，转写可得仍走 video skill，不可得才按 Intake 降级条款以简介为薄源。

工人 prompt 模板：

```
你是精读员，只读不写。原料：<unified_inbox.json 对应条目的 content / _raw/ 下文件路径（PDF 文本或兜底正文）/ 转写+简介>。
产出一张精读卡（markdown，≤600 字）：
- 核心论点（Thesis + Evidence + Strength，同 analyzer Step 2 维度）
- 关键术语/工具（出现了什么、怎么用的）
- 风险与反论（作者自己承认的 + 你看出的盲区）
- 《提及/引用作品清单》：文中点名的论文/repo/产品/文章（视频源优先吃简介 description，
  口播提及只作线索；过滤图床 URL；没有就写"无"）
只回卡片，不要复述全文。
```

## 关联合成（主对话做，吃卡片不吃全文）

- 跨篇找：一致结论 / 冲突观点 / 共同引用 / 时间脉络
- 强制带 H0 反框：「这几篇**共同预设**了什么？这个预设谁在质疑？」
- H0 产出的是**假设**，报告里必须标注"假设（未检索验证）"——除非走了下面的反方搜索

## 反方搜索（opt-in，用户说"找反方"才跑）

spawn 一个反方工人，硬规则：

1. **按主张不按作者**搜：从卡片抽出可检验的技术性主张清单再逐条找反证
2. **学术来源优先级**：OpenReview 该论文评审页（带 weaknesses 的真人反方）→ alphaXiv / HuggingFace 讨论 → Semantic Scholar citations 的引文上下文 → 通用 web 搜索兜底
3. **中文内容**：先抽可检验主张并**翻译成英文**搜英文世界的讨论；主张不可检验（纯观点/个人经验帖）→ 输出"无可检验主张，跳过"，**禁止**用中文关键词在微信生态硬凑反方
4. **防左右互搏**（最重要）：每条反对意见必须附可点开的 URL + 原文引句，且为本次检索所得；零命中就如实输出"未找到外部反方"，可以附"模型自检"段但必须显式标注"非外部观点"，**严禁**自产观点冒充专家归属
5. 报告强制分区：「H0 假设」与「sourced 反方」各自成段，不许混排

## 报告必备两段：教学层 + 大牛视角

用户的目的是**学习**，不只是信息消化。每份调研报告必须含这两段：

**教学层（第一性拆解 + 费曼白话）**：
- 从本批内容里选 ≤3 个核心概念，每个讲三件事：为什么存在（解决什么根本问题）/ 设计权衡（牺牲了什么换什么）/ 桥接已知——类比可用他的资产踩坑，也可用生活常识，**认知增量优先于项目效用**。桥接必须落到机制层：一句共享机制（都在解决什么问题）+ 一句关键差异/边界（哪里不能照搬）；只点名字不讲机制 = 空泛比喻，该概念教学段视为未完成
- 每个概念必须附一段**「讲给小朋友听」的白话版**（费曼式：不靠术语、用生活类比把最难的部分讲到外行能懂——写不出白话版 = 自己也没真懂，回去重读原文）
- 结尾附**费曼自测 3 问**：前 2 问考理解（why/权衡类，不出名词复述题，答案能在报告正文里找到）；第 3 问必须是**迁移题**——把本批某个核心概念迁移到一个新场景（优先用户的项目场景，内容与项目无交集时用生活/其他领域场景），无标准答案、不附参考答案

**大牛视角（真实专家评议）**：
- **人选跟着内容领域走，不锚定技术圈**：艺术文→该艺术领域的标志人物（乐手/导演/评论家），商业政治文→该领域思想领袖（企业家/经济学家/哲学家级人物），技术文→该细分方向的公认行业领导者。选人标准 = 这个领域里最有分量的声音，不是用户最熟的人
- 每位 2-3 句，用其**已发表立场**评议本批内容（不是泛泛介绍此人）
- 每条标注证据等级：「检索引证 ✅（附 URL）」或「公开立场推演 ⚠️（基于训练知识未本次检索）」——两级都允许，但必须标
- **禁止**虚构人物、虚构立场、把模型自产观点安到真人头上（同反方搜索的防左右互搏铁律）
- 前端主题可叠加本地 kaka-perspective skill 占一席；非前端主题不硬凑

## 报告骨架（落盘通用格式，不锚定具体笔记文件）

> 头部引用块：来源（含链接）/ 追引用来源 / 整理日期 / 关键词

0. TL;DR（≤5 句：跨篇关系 + 核验结论 + 对我的最大启发）
1. 信源分级表（性质 + 可信度星级）
2. 各篇要点卡；做过引用核验的必含「转述 vs 原文」三档对照表
3. 跨篇关联（一致 / 冲突 / 共同预设——H0 标注为假设）
4. 教学层（≤3 概念拆解 + 白话版 + 费曼三问）
5. 大牛视角（每条标注证据等级）
6. 裁决表 + 未覆盖清单 + 落盘清单

空段可省、顺序可按内容调整；**4/5 两段与未覆盖清单不可省**。

## 引用追溯与回流

- 日常形态 = 精读卡里的《提及/引用作品清单》，零额外成本
- 用户点名"追第 N 条" → 把该条当新 URL 回流 Intake 重抓
- 付费墙论文（ACM/IEEE/Springer）只到 arxiv abs / Semantic Scholar 摘要级元数据，标注"仅元数据可得"
- 追溯**封顶 1 跳**（按"把引用条目当新源回流 Intake 展开精读"计），防止引用图无限展开；为核实主张归属的定向 fetch **不计跳**，单批预算 ≤2 次，超预算列入「未覆盖清单」
- **主张归属核实是合成前默认动作，不需用户点名**：精读卡出现数字/分类/归属类断言、且来源属二手转述时，与一手文档对照；一手文档不在本批内，允许为定位原始出处做轻量 fetch（首跑战果：抓出"九类分法"非官方 3 类、"8-12 拐点"非官方 20-50）
- 回流重抓 / 归属核实拿到原文后的标准动作 = **逐条对照表**：从精读卡抽出依赖该引用的主张，每条给「转述版 vs 原文版（附原文引句）」+ 三档判定：一致 / 走样（含夸大、数字偏移）/ 查无（原文无此说法，附真实出处线索）；对照表强制进报告，判走样/查无的主张 Strength 以原文为准降级，不得沿用转述版评级
- Semantic Scholar API 细节：等真用到第二次再沉淀成文档，现在不预付

## 裁决与落盘

1. 用 SKILL.md Step 3 的 4 项目画像当闸门，每篇一行：「沾 <项目> + 一句为什么」或「纯学习」
2. 用户点头后才跑 project-suggest，且**单次最多对 1 个项目**：cd 到该项目根，把该批所有相关卡片打包成一次输入（不许按 篇×项目 循环）
3. 三 sink（**单次批量确认**）：终版报告末尾与「未覆盖清单」并排附「**落盘清单**」——复用 §1 的每篇裁决行，每行追加 sink 类型 + 目标路径 + 是否进 project-suggest 打包；用户一条回复确认/改写即执行全部写入（project-suggest 仍按 §2 单次最多 1 个项目）；仅裁决有歧义或涉敏感的条目标 ❓ 单独问：
   - 纯学习 → `~/Desktop/archives/技术总结/MM.DD-<标题>.md`（格式按上方「报告骨架」段，教学层与大牛视角两段必须随笔记落盘）
   - 真实需求 → `~/Desktop/cmm/agg/真实需求落档/MM.DD-<需求名>.md`
   - 生码灵感 → `agg/V0.0.6/参考与灵感.md` 的 📥 区
4. 报告末尾附「未覆盖清单」：哪些源没抓到真正文、哪些引用追不了、原因——绝不报假覆盖
5. **落盘确认只发起一次**：报告含齐必备两段与未覆盖清单、且用户已点名的追引用回流完成后即发起；之后的 opt-in 增强轮（追引用/反方）新发现，直接增量 append 进已落盘的 sink 文件并报一句路径，不重开整报告确认
