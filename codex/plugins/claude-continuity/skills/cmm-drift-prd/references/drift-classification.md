# Drift 三类判定规则

## 三方比对决策表

判定必须三方都做对比，**不能**只看注释 vs 代码或注释 vs PRD。

| 注释 vs 代码 | 注释 vs PRD | 代码 vs PRD | 分类 | 处理 |
|---|---|---|---|---|
| ✅ | ✅ | ✅ | 无 drift | 跳过 |
| ❌ | ✅ | ❌ | **C** | 🟡 出 diff 草稿不动 |
| ❌ | ❌ | ✅ | **A** | 🟢 (conf≥0.85) / 🟡 (低) |
| ✅ | ❌ | ❌ | **B + C** | B 改注释，C 出代码 diff |
| ❌ | ❌ | ❌ | **🔴** | 三方各异，PRD 可能有问题 |
| ✅ | ✅ | ❌ | **不可能** | 矛盾，重新跑判定 |
| ❌ | ✅ | ✅ | **A** (反向) | 注释抄错 |

---

## A 类：注释 ≠ 代码

### 定义

注释描述的行为与实际代码行为不符。注释可能：

- 抄错章节号（指向 PRD 不存在/无关的章节）
- 脑补功能（注释说"会缓存 5 分钟"，代码没缓存）
- 过时（早期实现的注释，代码后来重构没跟）

### 置信度规则

| 置信度 | 触发线索 |
|---|---|
| ≥ 0.95 | 数值/字符串/常量级别明确不一致 |
| 0.85 ~ 0.95 | 控制流/分支级别清晰不一致 |
| 0.70 ~ 0.85 | 模糊不一致（注释抽象、代码可能多种解读）|
| < 0.70 | 不标记 |

### 自动改阈值

- **≥ 0.85** → 🟢 自动改注释（贴合代码的描述）
- **< 0.85** → 🟡 只标记

---

## B 类：注释 ≠ PRD

### 定义

注释描述的行为与当前 PRD 章节内容不符（注释当时对应的是旧版 PRD）。

### 判定线索

- 注释里的功能描述与 PRD 当前章节描述明显不同
- 注释里的字段名 / 限制条件 / 默认值 PRD 改过
- 有 PRD 旧快照 → 精确知道哪段改了
- 无旧快照 → LLM 直接比对，置信度通常 ≥ 0.8

### 处理

**全部自动改注释**。理由：PRD 是 ground truth，注释跟随是 by-design。

但在 HTML 报告里**醒目列出**，便于用户事后 git diff spot-check。

---

## C 类：代码 ≠ PRD

### 定义

代码实现与当前 PRD 章节描述不符。可能是：

- 真 bug（PRD 说要 X，代码做了 Y）
- 未实现的功能（PRD 升级加了新条件，代码没跟）
- PRD 不可实现（罕见，转 🔴）

### 处理

- **绝不自动改代码**
- 全部进 🟡 档
- 输出建议 diff 草稿（"建议改成 X"），供用户手动 apply 或新开 PR

### diff 草稿格式

```json
{
  "code_diff_draft": {
    "file": "src/foo/bar.ts",
    "line": 42,
    "old": "const MAX = 20",
    "new": "const MAX = 50",
    "rationale": "PRD §5.1 默认 size 已升级到 50"
  }
}
```

不要让 LLM 自己 git apply 这个 diff，仅作为报告字段。

---

## 🔴 档：PRD 自身矛盾

### 触发场景

- PRD 同一章节内部矛盾（前后文打架）
- PRD 章节结构剧烈变动（章节号 + 标题都漂了，匹配不到）
- PRD 引用了不存在的其他章节
- PRD 同一概念多处定义且不一致

### 处理

不在本 skill 范围。生成转介绍信息：

```
建议跑 onlychat-prd-reflection：
- 涉及章节：§3.2
- 矛盾点：注册流程要求"邮箱验证"，但 §3.3 又说"匿名注册无需邮箱"
- 触发本扫描的代码：src/auth/register.ts:42
```

## Few-shot 示例

### 示例 1：A 类高置信（注释抄错数值）

```ts
// PRD §3.2 用户名长度限制 4-20
const MIN_LEN = 4
const MAX_LEN = 32   // ← 代码 32，注释说 20
```

- 三方核对：
  - 注释 vs 代码：❌
  - PRD 当前是 4-32 → 注释 vs PRD：❌
  - 代码 vs PRD：✅
- 分类：**A**，confidence 0.98
- 处理：🟢 自动改 → `// PRD §3.2 用户名长度限制 4-32`

### 示例 2：A 类伪装下的 C 类

```ts
// PRD §3.2 用户名长度限制 4-20
const MIN_LEN = 4
const MAX_LEN = 32
```

- 三方核对：
  - 注释 vs 代码：❌（看起来像 A）
  - PRD 当前是 4-20 → 注释 vs PRD：✅
  - 代码 vs PRD：❌（**真正问题在代码**）
- 分类：**C**
- 处理：🟡 不动代码，输出 diff 草稿 `MAX_LEN = 20`

**重点**：A 和 C 长得像，必须查 PRD 才能定性。

### 示例 3：B + C 复合

```ts
// PRD §3.2 注册需要邮箱验证
async function register(email: string) {
  await sendEmail(email)
}
```

PRD 当前 §3.2 改成「注册需要邮箱 + 手机号双验证」：

- 注释 vs 代码：✅（都只说邮箱）
- 注释 vs PRD：❌
- 代码 vs PRD：❌
- 分类：**B + C**
- 处理：
  - B：🟢 自动改注释 → `// PRD §3.2 注册需要邮箱 + 手机号双验证`
  - C：🟡 出代码 diff 草稿（需要补 `sendSms`）

### 示例 4：纯 B 类（注释落后于 PRD，代码已经领先）

```ts
// PRD §5.1 默认 size 20
const DEFAULT_PAGE_SIZE = 50
```

PRD 当前 §5.1 是「默认 50」（PRD 升过，工程师改了代码但忘了改注释）：

- 注释 vs 代码：❌
- 注释 vs PRD：❌
- 代码 vs PRD：✅
- 分类：**B**（不是 A，因为根因是 PRD 升级）
- 处理：🟢 自动改注释 → `// PRD §5.1 默认 size 50`

**判定关键**：A 与 B 的区分看代码 vs PRD 是否对得上。对得上是 B（PRD 升了），对不上是 A（注释错）。

### 示例 5：🔴 PRD 自身矛盾

```ts
// PRD §3.2 注册需要邮箱
async function register(email: string) {
  await validateEmail(email)
}
```

拉到 PRD：

- §3.2 标题：「注册流程」内容：「必须验证邮箱」
- §3.3 标题：「匿名快速入口」内容：「无需邮箱即可注册」
- 两章节定义打架

- 分类：**🔴**
- 处理：生成转介绍信息给用户，建议跑 `onlychat-prd-reflection`

## LLM 提示词模板

每个 anchor 比对时，给 LLM 三段输入：

```
你正在对 onlychat 项目代码做 PRD drift 三方比对。

## 当前注释块（含 anchor §3.2）
[贴注释文本]

## 对应代码块（注释下方 N 行）
[贴代码]

## PRD §3.2 当前内容
[贴 PRD 章节]

## 任务
按 references/drift-classification.md 的三方决策表，判定 drift 类型。

输出严格 JSON：
{
  "type": "A" | "B" | "C" | "RED" | "NONE",
  "confidence": 0.0~1.0,
  "rationale": "一句话说明三方比对结论",
  "new_comment": "如果可自动改注释，给新注释文本；否则 null",
  "code_diff_draft": "如果 C 类，给 {old, new, rationale}；否则 null",
  "red_reason": "如果 RED，说明 PRD 自身矛盾在哪；否则 null"
}

只输出 JSON 不要其它内容。
```

LLM 输出非 JSON 时：重试一次；二次失败 → 跳过该 anchor 进"解析失败"列表。
