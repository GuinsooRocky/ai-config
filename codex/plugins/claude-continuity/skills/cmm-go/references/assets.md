# 按需拉资产（第 4 步）

原则：**飞书是真相源，顺指针实时取，不缓存正文**。面板里 ● 有指针直接拉；○ 现搜飞书兜底。

## PRD / 飞书文档
- 有链接 → `mcp__social-proxy-documents__get_document`（吃 URL，大文档默认前 50000 字 + has_more，按 offset 翻页）
- 无链接 → `search_documents` 用「<feature名> PRD」搜，找到回填 features.md 这条的 `PRD:`
- **拉之前必须先确定范围**（见下面 §PRD 范围）。别一上来就 50000 字全塞。

## PRD 范围（scope）

为啥要范围：PRD 动辄几万字，session 上下文吃不消，且用户多数时间只在某几节打转。
解析顺序（在 SKILL.md §4 也写了，这里讲细节）：

1. **本 session 暂存** ← 开工口令同句吃下来的（SKILL.md §1）
2. **features.md 该项目的 `PRD范围默认:`**（非 `<待填>` / 非空才算）
3. **问一次** → 用户答完**写回 features.md 的 `PRD范围默认:`**（下次免问）

### 输入格式
- `all` / `全部` / `全量` → 不过滤，按 offset/limit 翻完
- `skip` / `不看` / `不用` → 本次不拉，记到 session 范围里（别反复问）
- 章节号列表：
  - 空格分隔：`3.1 3.4 4.1 8`
  - 逗号分隔：`3.1,3.4,4.1,8`（中英文逗号都吃）
  - 区间：`3.1-3.4` → 展开为所有 `3.1 <= x <= 3.4` 的同层节（按字典序逐段比较）
  - 混合：`3.1-3.4, 8` / `3.1 4.1-4.3 8`
- 中文章节号也吃：`三、3.1`、"第三章"按整章 → 等价于 `3`（覆盖 3 及 3.x.x）

### 写回 features.md 的规范化
用户答 `3.1, 3.4，4.1   8` → 规范化成 `3.1 3.4 4.1 8`（去逗号、压空格、保持原顺序）写回字段。
区间答 `3.1-3.4` 原样保留（别展开后写回，否则表里很丑）。

### 切片算法（仅 LLM 心算，不写脚本）

1. `get_document` 全文（必要时翻页直到 has_more=false 或确认想要的章节都拿到）
2. 按 markdown 标题行扫一遍，正则识别章节号：
   - `^(#+)\s+([\d\.]+|[一二三四五六七八九十]+(?:、))[\s、\.]*(.*)$`
   - 中文章节号 `三、` → 转成数字 `3` 再匹配
3. 章节号**前缀匹配**（按 `.` 分段比较，避免 `3.1` 误匹配 `3.10`）：
   - scope `3.1` 命中 `3.1` / `3.1.1` / `3.1.2.5`；不命中 `3.10` / `3.11`
   - scope `3` 命中 `3` / `3.1` / `3.1.1` / `3.4.2`
   - 实现：把章节号 split 成 `["3","1"]`、`["3","1","1"]`，scope 是后者的前缀切片即命中
4. 区间 `3.1-3.4`：取 scope 起止的层级 max，逐节按段位字典序比较
   - `3.1 <= 3.2 <= 3.4` ✓；`3.5` ✗；`3.1.1` ✓（属于 3.1 子树）
5. 切出每节正文 = 标题行 → 下一同级或更高级标题行之前的所有内容
6. 拼回给用户：每节前保留完整标题 `## 3.1 xxx`，节与节之间空一行

### 边界
- 章节号匹配不到任何节（标题写错 / PRD 改了）→ 报"未命中: 3.5"并列出 PRD 实际章节号目录让用户重选；不要静默兜底拉全文
- 文档非标准 markdown 标题（飞书有时返回纯文本带数字）→ 退化到"按行扫数字开头"，告知用户切片可能不准
- `skip` 状态下用户后面又说"看 PRD" → 不算违反，重新走解析（说明换主意了），但别问范围那道题（直接拉 all 或 features.md 默认；若两者皆空才再问一次）
