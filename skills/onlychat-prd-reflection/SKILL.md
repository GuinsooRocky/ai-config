# OnlyChat PRD 反讲

仅用于 onlychat 项目。反讲是 **PRD 的反向调试器**——把 PRD 矛盾 / 漏洞 / 反直觉摆桌上**现在解决**，不在代码里发现。PRD 改了重跑这个 skill 出新版本即可。

本 skill **自包含**：风格规范、自检清单全在本文，HTML 底稿在同目录 `assets/handbook-template.html`，不依赖任何外部 skill。

## 何时使用

- 用户粘 PRD（飞书链接 / 本地文本）+ "反讲" / "讲一遍 PRD" / "扫一遍 PRD"
- PRD 大版本改完，重跑刷新反讲文档
- 新功能开发前的需求消化阶段

## 何时不用

- 已经动手开发，要技术方案 → 普通开发流程
- PRD 还没出（只有口头需求）→ 先催 PRD
- 小细节改动（< 半天工作量）→ 不值得做反讲
- 查代码注释跟 PRD 同没同步 → 那是 `cmm-drift-prd`，不是本 skill

## 核心原则

1. **章节编号全用 PRD §X.X，绝不引入自己的 01/02/03** — PM 一眼跳回 PRD
2. **严格按 PRD 自上而下顺序串讲** — PRD 怎么排反讲就怎么排
3. **跨节合并必须 blockquote 显式说明** — 例 PRD §8.4 Mobile + §8.5 PC 合成一节讲时，头部要一句话讲清楚为什么合
4. **跨页面零件 inline 到首次使用处** — PRD §3 的图像上传 / 搜索框等公共组件，inline 进首次依赖章节，不抽公共节让读者来回翻
5. **弹窗用 `弹窗 N` 全文唯一编号** — 跨章节不重置；**不用 🪟 / 任何 emoji icon**
6. **📱/🖥️ 差异内联标** — 同一段 list/table 里用 emoji 区分，不分两份文档
6.5. **目录 ≤ 8 条，一节 h3 ≤ 3** — PRD 有十几节不等于目录要列十几条。把相邻章节合成一个
   `<section>`（如 §4.2.1/.2/.3 合成「§4.2 管理页·替换·移除」），原来的 h2 降成节内 h3、
   PRD 编号靠 `.badge-prd` 承载；原 h3 再降成 `.sub-head` 段首加粗。
   **立法理由**：2026-09-20 推荐模型批量管理反讲首版 17 节 43 个标题，owner 原话「小标题太多了 我看到哭想」
6.6. **表格只给「必须并排看」的二维对照** — A vs B 逐项差异、N 项 × 属性矩阵才用 `.matrix`；
   「名称 | 说明」型清单一律写成 `<ul><li><b>名称</b> —— 说明</li></ul>`。全文表格控制在个位数。
   ⚠️ 列头就是对照双方名字的表（如「弹窗 4 | 弹窗 5」）别转列表，会丢「哪句属于哪边」。
   **立法理由**：同上那份反讲 20 张表被判「能不能少一些表格 除非特别需要的」，砍到 5 张
6.7. **末节是「反讲话术」，只放真人开口会说的话** — 正文写「是什么」，末节写「怎么开口」：
   开场 + 逐段口语稿 + 收尾，就这些。朴素 `<p>`，段首一个加粗小词（开场 / ① 名词 / ② 入口…）。
   **不要**：彩色底框、灰字导演提示、「按 20 分钟备」类会议元说明、「被问到时怎么答」的问答预案。
   **去 AI 味**（owner 原话「这种煞笔话能不能不要 能不能去个 ai 味」）——以下一律禁止：
   「我今天讲三件事」类编号宣告、「一句话：」「简单说」「换句话说」、
   「后面我都按这个说」「我说一句自己的判断」这类**关于说话的说话**、
   破折号 `——`（口语里不存在）、三段排比、每段同构的总分总。
   改成真人腔：短句、口语词（就是 / 挺 / 一坨 / 顺手）、直接进内容不铺垫、
   要提醒的事说进那句话里（「还有个地方我改了 PRD 的写法：……」）。
   **还有一类要删：关于我自己决策的自述** —— 「PRD 没写这个，是我拍的」「这句是 PRD 自己点名提醒的」
   「你们那边也得按这个来，不然就错了」。直接说结论和要求（「你们那边聚合也得按这个键」），
   别给结论加「这是我拍的」标签，也别替对方描述他会怎么做错。
   owner 原话：「这种煞笔话也不要」（2026-09-20，第四次返工）
   **要什么先说，理由最多一句** —— 每段要么是「我要你给什么」要么是「我要你知道什么」，
   第一句就说出来，理由压一句跟在后面。别写「PRD 开头写的是 X，但 Y，所以 Z，我希望 W，
   不给的话我按 V 做」这种四五句铺垫。
   反例（5 句，owner 判「这种 b 话你也写的出来？就一句需不需要分页」）：
   「PRD 开头写的是老作者可能有成百上千个角色，但那张清单没分页也没上限。一个模型影响八百个
   角色，这一屏就是八百行。服务端那边定的是前端分页、服务端同步处理，一批多少条我希望接口
   告诉我，不写死在前端。接口先不给的话我按两百做。」
   正例（3 句）：「这张清单要不要分页。一个模型影响八百个角色就是八百行。一批多少条给我个数，
   不给我按两百做。」
   同批收紧的还有：PC 两栏那段（删「左边一直看得见」「PRD 自己写岔了」的来龙去脉）、
   空态问卷（删「这个我有点担心」的铺垫，直接说「票数肯定偏高，我埋个分母」）、
   分级分身（把「聚合的键是模型+分级」这个结论提到第一句，解释压后面）
   **立法理由**：2026-09-20 话术节三轮返工——先是绿底框+灰字旁白+时长说明被判「乱七八糟 / 屁话」，
   去掉后仍被判 AI 味（「我今天讲三件事」「开始之前对三个词，后面我都按这个说」），问答预案也被砍
6.8. **带框容器一节 ≤ 2，中性说明一律写正文** — 框是用来「跟周围性质不同」的，不是用来强调的。
   一节里超过两个底色块，读者就分不清哪个重要，整页变成花布。
   - **`.note` 已废弃**：中性说明就是正文，用 `<p>` 写，需要强调就段首加粗。别再往蓝框里塞。
   - **`.warn` 只给进了待决策表的矛盾**（带 Q/N 编号那些）。顺带发现的提醒、设计稿差异、
     现有缺口，写成正文段落、开头加粗一句，不占框。
   - **`.steps` 只给真有先后依赖的施工步骤**。产品动线（他看到什么→点进去→改完）是叙述，
     用连贯段落写，套进编号圆点流会被撑成一节一屏。
   - **`.cards` 双列只给真·两边对照**（好消息 vs 坏消息、替换 vs 移除）。单向内容别拆两栏。
   - 默认形态永远是 `<p>` + `<ul>`。想加框之前先问：这段跟上下文性质真的不同吗？
   **立法理由**：2026-09-20 同一份反讲，9 节塞了 50 个带框容器（21 warn + 14 note + 2 big-card
   + 5 card + 7 qrow + 1 scope），平均一节 5.5 个，owner 原话「真的太乱了 全是乱七八糟的格式」。
   owner 在学习材料侧早有同款判例（「眼花缭乱拼 card」「一章带框容器 ≤2」「底框只给性质不同的东西」），
   本 skill 此前没同步

6.9. **`<code>` 不带底块，并列标识符合成一个** — 底稿里 `code` 已改成「等宽 + 暖褐字」，
   不再是灰底圆角方块（`.note` 同批删除，见 6.8）。用旧底稿生成过的文档，把
   `code{padding:2px 6px;background:var(--code);border-radius:5px;` 换成 `code{color:var(--code-fg);` 即可。
   内容侧只守两条：**整句中文别套 `<code>`**；**并列的字段名写成一个 `<code>`**
   （`由 <code>a + b + c</code> 推出来`，不是六个 code 排一行）。
   **立法理由**：同上那份反讲全文 260 个 `<code>`，§3.1 名词表一行五个灰方块被判「乱七八糟」。
   根因是样式不是数量——底块一去，260 个也不糊

6.10. **元说明全文禁止，不只是话术节** — 「关于内容的内容」一律删，不是压缩。典型句式：
   「下面逐条写清怎么拍的、依据是什么、风险在哪」「先把映射表摆出来，后面所有讨论都建在这张表上」
   「这节是全 PRD 信息密度最高的一张表」「我把它拍平成可直接写代码的形态：」
   「先不看 PRD，用一个故事讲清楚」。
   **判据：把这句删掉，读者少知道了什么？答「没有」就删。** 标题已经说过的，正文不再说一遍
   （h2 写「决策台账 · 23 条全部已拍」，下面就别再来一句「共 23 条…下面逐条写清…」）。
   期待管理类的一句话可以留（「全部问题已拍完，不需要外部输入」），因为它是结论不是导航。
   **立法理由**：2026-09-20 同一份反讲栽了三次——先是话术节的绿底框 + 灰字导演提示（→ 6.7），
   再是话术开头「先说清楚几个词」（owner：「说这个话就是蠢」），最后是台账导语（owner：「这个也不需要吧」）。
   每次只修被点名那一处，规则没提到全文级，所以一犯再犯

7. **dev 第一人称 + 主动挑刺** — "我范围内"、"我没把握"；PRD 矛盾直接 ⚠️ warn block，结论就写在那个 block 里

7.5. **文末待决策表只收「必须别人答」的，自己拍掉的一条都不进** — 反讲的读者是 owner 和会上的人，
   他们要的是「PRD 有什么问题、你怎么处理」，不是我的决策账本。自己拍的决定，结论写在正文对应
   章节的 warn 里（「已拍：⋮ 菜单，整卡点击进替换。」），**不要再在文末抄一遍加依据和风险**。
   一份反讲若全部自己拍完 → **没有这一节**，末尾直接是「开工要什么」。
   正文也别留 `（QN）` 编号和「见台账」这类交叉引用——没有表可查的编号就是噪音。
   **立法理由**：2026-09-20 那份反讲 23 条全部自己拍，仍按旧规则生成了「决策台账 · 23 条全部已拍」
   整节（占全文 9%，7 张 qrow 卡 + 两组列表），owner 原话「都说了不要这个了 这个对我没啥用啊」。
   删节时发现 3 处正文 warn 的结论写的是「已拍：见台账。」——**这就是把结论放错地方的代价**：
   正文说不完整，非得翻到文末。先回填结论再删节
8. **每个论点都能 trace 到 PRD** — 章节用 §X.X 锚定，细节 bullet 该带 PRD 关键词 / 行号也别省

## 风格红线

- ✅ 手边有一份已确认过的反讲 HTML 就拿来当风格锚点；没有就照本文 §核心原则 + §HTML 生成规范 走（版式一律用 `assets/handbook-template.html`，别另起炉灶）
- ✅ 第一人称、敢下判断："这块 PRD 没写清，我倾向 A，因为……"
- ❌ 别打官腔："本文档旨在..." / "建议产品同学进一步明确..." 都不行
- ❌ 别看到 PRD 矛盾不说，自己脑补一个版本写进去 —— 矛盾要进 ⚠️ warn block + 待决策表
- ❌ 别堆形容词凑篇幅；一句能讲清的不写三句

## PRD 获取

按手头线索取 PRD 原文（替代旧 prd-extract 流程）：

1. **飞书 URL** → 用 `social-proxy-documents` MCP 的 `get_document` 拉全文。大文档默认前 50000 字 + has_more，按 offset 翻页**直到覆盖所有要讲的章节**（漏翻会把没读到的章节误判成「缺」）。
2. **本地文本 / 文件** → 用户直接粘的，或 `--prd-file <路径>`，Read 即可。
3. **只给了项目昵称没给链接** → 查 `~/Desktop/cc-memory/onlychat/features.md` 里该 worktree 的 `PRD:` 字段拿飞书链接，再走第 1 条。

## 工作流

### 模式判定

落地路径固定：`~/Desktop/cmm/onlychat-World-Path/MM.DD-<需求名>反讲.html`

- 路径**不存在** → Fresh mode（首次反讲）
- 路径**已存在** → Refresh mode（PRD 改了重跑，按 delta 更新）

### Fresh mode（首次反讲）

1. **拉 PRD** → 见 §PRD 获取
2. **提章节目录** — 从 PRD 提出 §X.X 骨架，决定反讲 h2 / h3 顺序
3. **起 HTML 骨架** — `cp` 本 skill 的 `assets/handbook-template.html` 当底稿（左侧粘性目录 + 进度条 + 暗亮双模已配好），不要手写版式；细则见 §HTML 生成规范
4. **按 PRD 顺序填内容** — 每节一个 h2 带 `<span class="badge badge-prd">§X.X</span>`；弹窗用 `<span class="modal-tag">弹窗 N</span>`
5. **同步记矛盾** — 读 PRD 时遇到矛盾 / 缺文案 / 反直觉，就地写进该节的 warn（带 PRD 出处 §X.X 或行号）
   + 当场给结论。能自己拍的拍掉，只有**必须别人答**的才留成待决策（见原则 7.5）
6. **挑刺自检** — 见 §自检清单
7. **文末待决策（可能为空）** — 只收必须别人答的，P0 用 `.qrow`（必须含 PRD 出处）。
   **全部自己拍完就没这一节**，别为了有个收尾而把自己的决定列成台账（原则 7.5）
8. **末节写反讲话术** — 见原则 6.7；只有开场 / 逐段口语稿 / 收尾，朴素段落，去 AI 味

### Refresh mode（PRD 改完重跑）

判定：落地路径已存在 → 刷新而非重写。

1. **拉新 PRD** + Read 旧反讲 HTML
2. **diff PRD § 树**：
   - 旧反讲覆盖了哪些 §？提取 `<h2>...§X.X</h2>` 列表
   - 新 PRD 哪些 § 改了内容 / 新增了 / 删除了
3. **定向重写受影响的节**，unchanged 节保留原文（别全文重跑浪费 + 引入 drift）
4. **顶部 cover 加"更新记录"块**：用 blockquote 列出本次刷新覆盖了 PRD 哪几节、增删了什么、新增 / 解决了哪些 Q
5. **待决策表迭代**：PM 已答的 Q **保留编号**改成 ✅（或移到"已决"分组），不要让 Q2 升格 Q1（保历史 trace）；新发现的矛盾插到 P0 / P1

**Refresh 必做检查**：
- 保留旧 Q 编号
- 待决策 Q 删除时，正文 `（见 QN）` 交叉引用同步清理（grep `见 Q` 验证）

## HTML 生成规范

单文件 HTML，`<style>` 内联，**不外链**。暗 / 亮双模（跟随系统 + 顶部一个手动切换按钮）。可发飞书 / 群、可打印。

**必备 CSS 类（类名固定，下游靠它认结构）**：

| 类名 | 用途 |
|---|---|
| `.badge-prd` | 章节徽章，显示 §X.X，跳回 PRD 用（底稿里就叫这个，别写成 `badge badge-prd`） |
| `.modal-tag` | 弹窗 N 唯一编号标记 |
| `.warn` | PRD 矛盾 / 风险的 ⚠️ 警示块 |
| `.qrow` | 文末 P0 待决策卡片（含 PRD 出处） |
| `.big-card` | 整页一句话的大字强调卡（克制用，全帖 1~2 张） |
| `.plat-pc` / `.plat-mobile` | 🖥️ / 📱 平台差异内联标 |

**底稿：`assets/handbook-template.html`（cp 一份改，别再手写版式）**

反讲动辄十几节 + 十几个 Q，PM 在会上要来回跳 —— 单栏无目录的页面撑不住。底稿是学习手册式：

- 顶端标题栏 + **左侧 190px 粘性目录** + 正文最大宽 1120px + 顶部阅读进度条
- 900px 以下自动收起目录转单栏；`@media print` 已配好（去目录/进度条/切换钮，warn 与 qrow 不跨页断）
- 暗 / 亮双模：跟随系统 + 右上角手动切换按钮

> 底稿来自 codex 侧 `~/.codex/skills/longform-html/assets/learning-handbook-template.html`，
> 已在本 skill 的 assets 下**落成独立副本**并补了暗色 token（原稿是 light-only，与自检第 12 条冲突）
> 与反讲专属组件。**用本地这份，不要跨 skill 目录引用**，本 skill 仍是自包含的。

**除上表的必备类外，底稿还带这些通用组件**（够用就别自造）：

| 类名 | 用途 |
|---|---|
| `.matrix` | 对照表（表头深绿反白），凡是「N 项 × 属性」一律用它，别写成散文 |
| `.card` / `.cards` | 单卡 / 双列卡片组。**双列只给真·两边对照**，单向内容别拆两栏（原则 6.8） |
| ~~`.note`~~ | **已废弃，别用**（见原则 6.8）。中性说明写 `<p>` 正文，要强调就段首加粗 |
| `.steps` | 带序号圆点的施工步骤流。**只给真有先后依赖的步骤**，产品动线用正文段落（原则 6.8） |
| `.diagram` | 深色等宽块，画链路 / 流程 ASCII 图 |
| `.scope` | 绿色范围声明块（只反讲部分章节时，开头必放） |
| `.section-kicker` | h2 上方的小号橙字眉标 |

**用法**：cp 底稿 → 换 `{{TITLE}}` → `<nav>` 里逐节补 `<a href="#s-3-1">§3.1 …</a>`（**每项必须指向真实 section 的 id**）→ `<main>` 里每节一个 `<section id="s-X-X">`。

## 自检清单

落档前逐条过（对应 §核心原则，全 ✅ 才算交付）：

1. 章节号全是 PRD 的 §X.X，没有自创 01/02/03？
2. 反讲顺序 == PRD 自上而下顺序？
3. 跨节合并处都有 blockquote 讲清为什么合？
4. 公共零件（上传 / 搜索框等）inline 在首次使用处，没单抽公共节？
5. 弹窗编号全文唯一、不重置、无 emoji icon？
6. 📱/🖥️ 差异用内联标，没拆成两份文档？
7. 每个 PRD 矛盾都进了 ⚠️ `.warn` 块 + 文末待决策表，没有脑补版本？
8. 每个论点都能 trace 回 §X.X（带关键词 / 行号）？
9. 全文第一人称、有判断、无官腔？
10. 待决策表里每条都是**别人不答就开不了工**的？自己拍掉的有没有混进去（原则 7.5）？
    正文没有 `（QN）` 孤儿编号和「见台账」这类交叉引用？`grep -nE '（[QN][0-9]|见台账' 验证
11. 飞书大文档分页翻全了，没有把没读到的章节误判成「缺」？
12. 只产出 `.html`，没留中间 `.md`？暗/亮双模都正常？
13. 左侧目录每一项都指向真实存在的 `section` id，点了真能跳？没有孤儿锚点 / 漏掉的节？
14. 「N 项 × 属性」的内容都进了 `.matrix` 表，没有摊成散文让读者自己重拆？
15. **数一遍带框容器**：`grep -o 'class="[^"]*\(warn\|note\|card\|scope\|big-card\)' 文件 | wc -l`
    除去文末 `.qrow`，平均一节超过 2 个就是花布，把没带 Q/N 编号的 warn 和全部 note 化成正文重数。
16. **元说明扫一遍**：`grep -nE '下面|接下来|先把|本节|这一节|逐条写清|我把它|用一个故事' 文件`
    ——命中的每一句问「删掉读者少知道什么」，答不出来就删（原则 6.10）。
17. `code` 的 CSS 是 `color:var(--code-fg)` 而不是灰底方块？并列字段名合成了一个 `<code>`，没有六个排一行？
18. 末节「反讲话术」只有开场 / 逐段口语稿 / 收尾？没有底框、灰字旁白、时长说明、问答预案？
    通读一遍：有没有「我今天讲三件事」「一句话：」这类宣告体，有没有破折号和排比？有就是 AI 味，重写。
19. 话术节的排序是**一条动线走到底**（他看到什么 → 点进去 → 改完 → 结果），技术约束和接口清单
    收在动线讲完之后？没有把「落库」「规模」「PC 端」插进动线中间把它切断？
    **立法理由**：2026-09-20 话术按 ①名词②入口③管理页④确认⑤落库⑥规模⑦电脑端 编号排，
    owner 判「话术不能是这种排序」——⑤⑥ 打断动线，⑦ 又把整条动线用 PC 重放一遍
