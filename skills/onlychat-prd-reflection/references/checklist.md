# 反讲挑刺清单

读 PRD 时**同步开个待决策**列表，往里塞符合下列任一条的发现。

## 12 条挑刺模式（按优先级）

### A · PRD 内部自相矛盾（P0）

1. **同一节内数值冲突** — 例 §8.6.2 同一节里"≤5 / 计数器 /5 / Up to 6 toast"三处自相打架。**列出每一处的原文 + 出处**，让 PM 看一眼就定位
2. **跨节同名不同义** — 例 §8.3.3 写 `Basic Info`，§8.6 + §8.9.1 都用 `World Info`。标 PRD 自己默认用哪个
3. **新旧版本残留打架** — PRD 改了某节但忘了同步其它引用。例：校验链从 4 步简化为 3 步，但别的章节还引用旧步号

### B · 反直觉设计（P0）

4. **主次按钮顺序反**——PRD 写"主=Back / 次=Confirm"很可能是故意"劝退路径放主按钮"，但也可能是笔误。**直接问 PM "是的就这么放？"**
5. **默认值反直觉** — 例如默认勾选高破坏性选项

### C · 缺信息（P0 / P1 看场景）

6. **缺关键文案** — 错误提示 / 占位符 / toast 文案 PRD 没给（除非 PRD 已给文案，那就抄上不留 Q）
7. **缺接口约定** — 例 🪟11 Visibility 二确需要 `getWorldCardUsage` 接口，PRD 没说接口形态
8. **缺 Figma** — 不阻塞反讲产出，但标 P1
9. **缺 URL / 帮助文档** — 例如 View Guide 跳到哪？产品配置写死的 URL 哪里取？

### D · 边界 / 状态机不全（P0）

10. **边界值临界行为不显式** — "字符数到 4000 时？满额还允许保存吗？" / "数字到边界变色规则是 ≥ 还是 >？" PRD 常忽略。反讲必须明确每个边界
11. **失败链路不全** — 例 Import Loading → 失败：网络挂 vs 解析失败 vs 用户主动关 vs 杀 APP，4 种行为分别是什么？PRD 经常只写其中一两种
12. **状态转移有遗漏分支** — 例 Visibility Private → Public 的反向路径行为不对称。或 Tab 切换时未保存的处理

## E · "MVP 不做" 项的处理

PRD 飞书最新版常标"MVP 不做"——这些**不进待决策**，但反讲里要 ⚠️ 警示框醒目重述，避免：

- 后人按 PRD 看到了未删的旧描述，去做了
- 设计 / QA 来挑"这个怎么没做" 时有 callout 可指

## F · 跨需求 / 跨页面对齐（P1）

- **复用 OC 既有组件是否对齐**：例如世界卡里的 Rating / Gender / Age，跟 OC 编辑器里的字段语义一样吗？
- **Tag 池**：Genre 8 项 + Content Tags 4 组，是新建还是复用 OC 现有 Tag 系统？
- **跳转目标**：发布成功跳"个人主页"，个人主页是改版版本（指向另一份文档）还是当前版本？

## 反讲提交前自检（写完 grep 这几个）

```bash
FILE=~/Desktop/cmm/onlychat-World-Path/MM.DD-需求名反讲.html

# 1 · 没有残留的"自己编号" 01 / 02 / 03
grep -nE 'class="num"' "$FILE" && echo "❌ 有残留自定编号" || echo "✅ 编号全用 §X.X"

# 2 · 没有残留 🪟 emoji
grep -n "🪟" "$FILE" && echo "❌ 还有 🪟" || echo "✅ 弹窗 marker 已纯文字化"

# 3 · 所有 h2 都带 § PRD badge（除 cover h2 / 范围 h2 / 待决策 h2）
grep -nE '<h2>' "$FILE"
# 人眼检查：除了"反讲范围"和"N 个待决策"两个 h2，其它都应该带 §X.X

# 4 · 待决策 Q 引用要清零悬挂引用
grep -n "见 Q" "$FILE"
# 列出来的所有 Q 编号必须在文末待决策表里存在

# 5 · §X.X 引用要双向（正文有引用，文末有出处，反之亦然）
grep -oE '§[0-9.]+' "$FILE" | sort -u
# 人眼扫一遍，看有没有引用了但没讲到的 §
```
