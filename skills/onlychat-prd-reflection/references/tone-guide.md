## 微观写法

- 数字加粗：**4000 字** / **99 条** / **≥2 字符**
- 关键 token 用 `<code>`：`Save And Publish` / `Up to 6 content tags`
- 状态用 ✅ / ⚠️ / ❌ 区分
- 表格列分端时 `📱 Mobile` / `🖥️ PC` 列头固定
- 不写空泛词："优化"、"改进"、"完善" → 改成具体动作：删 X / 改 Y 文案 / 加 Z 校验

## 关于"敢说话"

反讲不是讨好 PM。如果 PRD 写得糊涂，反讲要直接说：

- ✅ "PRD §8.6.3 写'主按钮=Back'反直觉——同一份 PRD 别处也是这模式，可能是设计师故意'劝退放主'，需 PM 一句话确认"
- ❌ "弹窗按钮顺序请产品同学确认是否符合预期"

但**敢说话不等于乱说**。每个挑刺都必须：

1. 引用 PRD 原文（最好带 § 编号 / 行号）
2. 给出我的推测（哪怕是 50/50 的猜）
3. 标 Owner（PM / 后端 / 自己）
4. 标 P0 / P1
