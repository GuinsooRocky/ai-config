# 合并与对照规则（模式 B / C 用）

## 模式 B：一致性合并 → `主线.md`

读 `cards/` 全部卡片，产出/更新 `docs/research/anthropic/主线.md`。**覆盖重写整份**，
不是追加——主线库是终态文档，不留演进过程。

四节，缺一节不可：

### 1. 主线
判据：**同一个赌注被 ≥3 张卡支撑，且跨度 ≥2 个月**。只在一个月里密集出现的多半是一次
发布周期的配套宣传，不是主线。

每条主线写：

- 赌注（一句话）
- 支撑卡片：`slug`（日期）× N
- 证据强度：按支撑卡片的「证据类型」分布定 —— 实验数据/事故复盘 = 硬，内部实践 = 中，
  立场声明/产品发布 = 软。三篇软证据不等于一篇硬证据，如实标。
- 时间跨度：首次出现 → 最近出现

### 2. 口径变化
同一主题前后说法变了。写成时间线，明确「从 X 变成 Y」，并注明是**补充**（原来的还成立）
还是**取代**（原来的被推翻）。这两者对下游判断完全不同。

### 3. 张力
两条主线互相拉扯、没有被调和的地方。明写「A 说…… / B 说…… / 没见到他们处理这个矛盾」。
**别替他们圆场**——找到的张力往往比找到的主线更有价值，那是他们自己还没想清楚的地方。

### 4. 孤点
只出现 1-2 次、够不上主线、但足够反直觉值得留着的。单列，别丢。今天的孤点常是明年的主线。

## 模式 C：对照 soliloquy → `对照-YYYY-MM-DD.md`

输入：`主线.md` + soliloquy 的 `docs/prd/PRODUCT.md`、`REDLINES.md`、`BACKLOG.md`
（有 `WORLDCARD-CHARTER.md` 也读）。

每条主线给一个判定，四选一：

| 判定 | 要求 |
|---|---|
| **已对齐** | soliloquy 已经在做。**必须引具体文件路径或已拍的决定** |
| **相悖** | 现有决定跟这条主线冲突。引出那个决定 + 说清冲突点在哪 |
| **空白机会** | 没做、可做。给一条能直接进 BACKLOG 的动作：一句话、可验收 |
| **不适用** | 这条对消费级陪伴产品不成立。**说清为什么**，别只写"不适用" |

### 四条硬约束

1. **禁脑补。** 每条判定必须引 soliloquy 仓里真实存在的文件路径 / 已拍决定 / 代码。
   引不出来就标 **【无依据·待查】**，不许用「soliloquy 应该……」「建议 soliloquy……」
   这种无主语句式蒙混过去。这一层没了证据就是一堆听着有道理的废话。

2. **禁直搬。** Anthropic 是模型/API 公司，soliloquy 是消费级陪伴产品。
   「Anthropic 说 X，所以 soliloquy 也该 X」是本 skill 头号反模式。
   每条【空白机会】必须写出**迁移路径**：这条主线在 B 端成立的原因，在消费端还成不成立、
   为什么。迁移路径写不出来 → 判【不适用】。

3. **【空白机会】最多 5 条。** 超了说明在凑数。宁可 2 条硬的，不要 8 条软的。

4. **不许动 BACKLOG.md。** 只产出建议文件。进不进 backlog 是 owner 拍板，
   本 skill 越界改需求库等于替 owner 做了决定。

### 一致性 ≠ 模仿

owner 要的是「方向上不打架」，不是「跟着 Anthropic 做」。所以【相悖】这一档要认真用——
soliloquy 有意选了跟 Anthropic 相反的路（比如公开面不做成人分级过滤，那是 owner 已拍的板），
如实标成【相悖·有意为之】，不要当成待修的 bug 报上去。
