# 卡片 schema（模式 A 用）

一篇文章一张卡，落 `docs/research/anthropic/cards/<YYYY-MM-DD>-<slug>.md`。

**schema 是这套机制的地基。** 跨篇一致性只有在卡片同构时才算得出来——某次跑偷懒改了字段，
那一批卡片在后续合并里就等于废了。字段全部必填，确实没有就写「无」，留空会被合并环节
当成「漏读」而不是「没有」。

## 模板

```md
---
slug: building-effective-agents
section: engineering
date: 2024-12-19
title: Building effective agents
url: https://www.anthropic.com/engineering/building-effective-agents
---

## 主张
<一句话：这篇在**主张**什么，不是"讲了什么"。>

## 押的赌注
<0-2 条：他们赌哪件事会成真、赌哪条路是对的。>

## 证据类型
<从固定表里选，可多选：实验数据 / 内部实践 / 立场声明 / 产品发布 / 事故复盘 / 用户数据>

## 复现术语
<他们的自造词和关键词，**英文原样照抄**>

## 对消费级 AI 陪伴产品的可迁移点
<0-3 条，无关就写「无」>

## 原文里最反直觉的一句
<英文原句照抄 + 大致出处>
```

## 逐字段填写规则

**主张** — 必须是可被反驳的断言。判据：这句话有没有可能是错的？没有可能错的就不是主张，是摘要。

| | |
|---|---|
| ✅ | agent 的能力上限由 harness 决定，不由模型决定 |
| ❌ | 介绍了如何设计 agent 的 harness |

**押的赌注** — 主线的真正原料。主张会换措辞、换例子，赌注不会。填那句「他们在赌……」。
例：「他们赌简单可组合的模式会赢过复杂框架」。

**证据类型** — 决定这条主张有多硬。合并成主线时，三篇立场声明的分量不等于三篇实验数据，
这个字段就是给那一步用的，别嫌机械。

**复现术语** — **必须英文原文照抄**（context engineering、harness、subagent、model welfare…）。
主线是靠术语复现被认出来的，翻译成中文就认不出跨篇的同一个词了。

**可迁移点** — 这栏是整套机制最容易腐坏的地方。Anthropic 是模型/API 公司，soliloquy 是消费级
陪伴产品，**大部分文章跟它无关是正常的**。无关就写「无」，硬凑会让主线库注水，几轮之后整套
东西就没人信了。

**最反直觉的一句** — 双重用途：将来回查原文的锚点，以及一个防跑偏的自检——如果一篇文章你挑不出
任何反直觉的话，多半是没读进去，或者这篇确实没营养（那就在主张里如实写「无新主张，属公告类」）。

## 抓取方式

英文站，**WebFetch 直接读**，不要走 sf-reader（那是给微信/小红书等中文平台的登录态通道）。

## 派工

每篇派一个子 agent 读全文出卡片，主对话只收卡片路径，不收全文——一篇长文动辄几千词，
灌进主对话会把后续的合并环节挤没。多篇之间无依赖，**一次消息里并行扇出**。
