把一个模糊想法逐级展开成能施工的 PRD。**每一级必须等用户确认后才往下展**——这是全流程唯一的硬规矩。

来源：Dex Horthy（HumanLayer 创始人）2026-07 访谈。原话：「如果你把自己的思考外包出去，你得到的就会是垃圾。」逐级展开是他对抗这件事的方法——每级都有人把关，把最终产出可能偏到哪去的**概率范围**一路收窄。

## 何时使用

仅用户**主动呼叫**才启动。典型场景：用户能用两三句话说清一个想法，要把它变成能施工的文档。

跟邻居的分工，别抢活：

| 场景 | 归谁 |
|---|---|
| PRD 已存在，拿方案对照它逐点拷问 | `grill-with-prd` |
| 想法模糊，用户自己都说不清要什么 | `brainstorm` |
| **想法能一口气说完，要展成 PRD 级文档** | **本 skill** |
| 方案已成形，找漏洞 | `grill-me` |

判据一句话：用户**能说完** → 本 skill（展开）；用户**说不清** → `brainstorm`（先问）。

## 四级阶梯

```
两句话（用户给）
  ↓ 展开 · 用户确认
一页：谁的什么问题、成功长什么样、明确不做什么
  ↓ 展开 · 用户确认
三页：主链路分步、关键分支、数据与状态、已知风险
  ↓ 展开 · 用户确认
十页大纲：逐节标题 + 每节要点，到能直接施工的粒度
```

## 步骤

### 步骤 1 — 接住想法，展成一页

约 400–600 字，**必须**含四块：

- 谁的什么问题（具体到人和场景，不要写"用户想要更好的体验"）
- 成功长什么样（可判定：能看到什么/能做到什么，不要写"提升满意度"）
- **明确不做什么**（这块最省事，不许跳过）
- 我最不确定的 2–3 处

写完**停下等确认**。用户没说"继续"绝不往下展。

### 步骤 2 — 展成三页

**必须**含：

- 主链路：用户从哪进来、经过哪几步、在哪结束
- 关键分支：空态、失败、权限不足、并发——每个分支的行为
- 数据与状态：要存什么、谁改它、什么时候失效
- 已知风险 + 我最不确定的 2–3 处

用户在步骤 1 改过的地方，**必须**往下游传，不要只改当前级。写完停下等确认。

### 步骤 3 — 展成十页大纲

**必须**含：

- 逐节标题 + 每节 3–5 条要点
- 每节标注：这节做完怎么验（可机械判定的验收条件）
- 施工顺序建议 + 每步的**可见/可测切片**（先 mock+界面立起来，别按"数据库→服务层→API→前端"横向排）

### 步骤 4 — 收尾

问用户两件事：

- 存哪（默认 `docs/prd/designs/<YYYY-MM-DD>-<主题>.md`，跟着项目的文档约定走）
- 接下来直接施工，还是先过一遍 `grill-with-prd` 自我拷问

**绝不**自动 commit、**绝不**自动调用实现类 skill。

## 输出格式

每一级的产出固定三段，顺序不许变：

```
## <第 N 级：一页 / 三页 / 十页大纲>

<正文——按对应步骤的必含块展开>

---
**我最不确定的：**
1. <具体到哪一处、为什么不确定、错了会怎样>
2. …

**要我往下展成 <下一级> 吗？** 或者你先改这一级。
```

硬约束：

- 篇幅按级走，**不要**在第一级就给出三页的量
- "最不确定的"**必须**具体到某一处决策，不许写"整体方向可能有偏差"这种废话
- 结尾**必须**是那句停下等确认的话，不许自己接着展

## 反模式

1. **跳级** —— 从两句话直接给十页大纲。这正是本 skill 要防的"把思考外包出去"，绝不允许。
2. **追求完美文档** —— 目标是压缩不确定性，不是把每级写到无懈可击。用户说"这级够了"就往下走，不要自己加戏。
3. **报喜不报忧** —— 省掉"我最不确定的"那段。那段是本 skill 的价值所在，缺了等于没展开。
4. **自作主张往下展** —— 用户没确认就继续。停下等待不是磨蹭，是这套方法的全部机制。
5. **顺手写代码** —— 产出只有文档。用户说"开工"时本 skill 已退场。

## 示例输出

用户给的两句话：「想让用户能把喜欢的角色收藏起来，现在只能靠翻历史记录找。」

第 1 级产出节选：

```
## 第 1 级：一页

**谁的什么问题**
重度用户（聊过 20+ 角色）想回到某个特定角色时，只能在会话列表里往下翻——
列表按最近活跃排序，三天前聊过的角色可能已经翻两屏。

**成功长什么样**
用户能在 2 次点击内回到任意一个标记过的角色；标记动作本身不超过 1 次点击。

**明确不做什么**
- 不做收藏夹分组/文件夹（先看有没有人用，再谈组织方式）
- 不做跨设备同步（本期只落本地，同步归后面的账号体系）
- 不做"最近常聊"自动推荐（那是排序问题，不是收藏问题）

---
**我最不确定的：**
1. 收藏入口放会话列表长按、还是角色详情页的显式按钮——前者省一次跳转但发现性差
2. 收藏后在哪展示：导航加一个"收藏"视图，还是会话列表置顶一段
3. 上限要不要设——不设的话重度用户可能收藏 50 个，那这个功能又回到"翻列表"

**要我往下展成三页吗？** 或者你先改这一级。
```
