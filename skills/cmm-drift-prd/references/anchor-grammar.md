# PRD Anchor 识别规则

## 支持的 anchor 模式

按优先级：

### 1. 章节号锚（主流）

`PRD §X.Y(.Z)` — 例如 `PRD §3.2.1`、`PRD §3.2`

- 允许 `PRD` 和 `§` 间任意空格
- 允许 `§` 和数字间任意空格
- regex: `PRD\s*§\s*\d+(?:\.\d+)+`

### 2. Token 锚（指定 PRD 来源）

`PRD<别名> §X.Y` 或 `PRD: <docx-token> §X.Y` — 多 PRD 时消歧义

- regex: `PRD\s*[<:]\s*([\w-]+)\s*[>]?\s*§\s*\d+(?:\.\d+)+`

### 3. 裸章节锚（弱信号）

`§X.Y(.Z)` — 例如 `§3.2`

- 噪音较大（数学符号、文献引用、法律条款都用 §）
- 仅在已确认是注释行时启用
- regex: `§\s*\d+(?:\.\d+)+`

## 不支持

- **标题文字锚**（如 `PRD 用户登录流程`）— 模糊匹配代价大且歧义多
- **飞书 block_id 锚**（如 `block:XXXxxx`）— onlychat 实际未使用
- **链接锚**（如直接贴 feishu URL）— 太松散

## 章节双 key 锚定

为对抗 PRD 改版章节号漂移（§3.2 → §4.1），每个 anchor 在 PRD 端必须解析为：

```json
{
  "section_number": "3.2.1",
  "section_title": "用户注册流程"
}
```

匹配优先级：

1. **强匹配**：章节号 + 标题文字都对得上
2. **drifted 匹配**：章节号变了但标题文字稳定 → fuzzy match（标题相似度 ≥ 0.8）找新章节号，标记 `section_drifted: true`，报告里要在该 anchor 处提示「PRD 章节号已变更：§3.2 → §4.1」
3. **失锚**：章节号 + 标题都漂了 → 进 🔴 档

## 注释块界定

找到 anchor 行后，向上下扩展找完整注释块：

- **JS/TS/JSX/TSX**：
  - `// …` 连续行 → 块
  - `/* … */` 多行块
  - JSX `{/* … */}` 块
- **Python**：`# …` 连续行；模块/函数顶部 `"""…"""`
- **Vue/Svelte**：模板 `<!-- … -->`、`<script>` 内同 JS

注释块的下方第一段非空代码 = 该 anchor 关联的代码块（默认 20 行内或到函数体结束）。

如果注释块**跨函数边界**，向下截到函数体结束（用 `}` / `def `/ `function ` 等粗略判定即可）。

## 误报防控

必须排除以下情况：

- `§` / `PRD` 出现在**字符串字面量**里 → 不算 anchor
  - 简化判定：行首 `^\s*(?://|/\*|\*|#|<!--)` 才算注释
- 多行字符串里的 § → 不算（除非外层是 docstring）
- `PRD` 出现在 import / 变量名 / 函数名里 → 不算

MVP 实现：

```python
def is_comment_line(line: str, lang: str) -> bool:
    stripped = line.lstrip()
    markers = {
        "py":   ["#", '"""', "'''"],
        "ts":   ["//", "/*", "*"],
        "js":   ["//", "/*", "*"],
        "tsx":  ["//", "/*", "*", "{/*"],
        "jsx":  ["//", "/*", "*", "{/*"],
        "vue":  ["//", "/*", "*", "<!--"],
        "md":   ["<!--"],
        "sh":   ["#"],
    }.get(lang, ["//", "#", "/*", "*"])
    return any(stripped.startswith(m) for m in markers)
```

进阶（可选）：用 tree-sitter 做语法级判定，能精确识别注释 token，避免字符串误判。MVP 不强求。

## anchor 多重出现

同一文件可能多处引用 `§3.2`（注释、文档字符串、多处实现）。处理策略：

- 每个 anchor 出现都作为独立条目扫描
- 同一 (anchor, file) 多次出现 → 在报告里合并展示，但 Edit 时各自独立
