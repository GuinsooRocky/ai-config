# 每章：定义 + 八块，写法与 ❌ / ✅

例子统一用「DAG 任务板 · 第 2 章 派活」，贯穿例是一张 12 节点的付费墙上线板。

**先说页面长什么样：** 下面的块是写作顺序，不是卡片。页面上定义、情境、概念、演示都是普通段落，不带块名、不带底色；「先做」是一段带输入框的正文，只有一个小标签；练习集中在一个细左线容器里，标题「练习」，回头题是其中最后一道；「这里容易想错」「本章加进规格的」是两个 h3。每章有底色 / 边框的容器 ≤ 2。

## 0 · 定义（读者：一屏内知道这词是什么）

- 每章第一屏；读者默认零基础，本章要用的词全在这里给名字
- 大白话、字面拆开、带一个读者天天在用的例子；不超过一屏
- 第 0 章的定义块讲的是全书主题词本身（DAG = 图 / 有向 / 无环），不是「怎么学」
- 对应：认知负荷理论的样例效应——没有图式的读者先给图式，再让他生成

```
❌ 全书只有一句话要背：DAG 任务板 = 有向无环图 + 节点是声明 + 翻绿权在验证器。
   （「有向无环图」当已知词直接用，读者读了 1/3 还不知道 DAG 是什么）
✅ 拓扑排序：把点排成一列，保证每个点都排在它所有前置的后面。做法叫 Kahn：
   先取前面没人的点，取走后擦掉它们指出去的箭头，再取新的没前置的点，循环到取完。
   关键路径：从起点到终点估时加起来最长的那条线，它决定总工期。
```

## 1 · 情境（读者：感到痛）

- 3–5 行，贯穿例上出一件具体的事，带人物和数字
- 先有问题再有概念；本块不出现任何术语
- 对应：Merrill 问题中心、Gagné 引起注意、UbD 基本问题

```
❌ 拓扑排序是 DAG 上最基础的算法，本章介绍 Kahn 算法与关键路径。
✅ 你有 5 个 agent，板上 12 个节点全是 open。第一分钟派谁？最多能同时忙几个？
   老板问「几点能上线」，你手上只有每个节点的估时。
```

## 2 · 先做（读者：猜 / 算 / 写）

- **在定义之后、概念展开之前**。零基础读者没有定义就是盲做；有了定义再给一个能起步的任务，留输入框
- 答案折叠在下方，标「对照」；不是「答案」——读者做的可能比参考更好
- 对应：Make It Stick 的生成效应、Merrill 激活、Gagné 唤起旧知

```
❌ 先想一下：什么是关键路径？（读者没法起步，只能往下翻）
✅ 在下面 12 行里圈出「没有前置」的节点；再圈出它们完成后能开工的第二批；
   最后凭直觉估一个总时长写在框里。
```

## 3 · 概念（读者：读）

- 第一句接读者刚做的结果：「你圈出的四个就是入度为 0 的节点」
- 术语最后给：先描述机制，再说「这个叫 X」
- 一个概念一段，不写「首先 / 其次」
- 对应：Gagné 呈现 + 引导、Diátaxis 具体 / 小步

```
❌ 拓扑排序（Topological Sort）是指……
✅ 你圈出的 N1 / N2 / N4 / N9 有个共同点：没人指向它们。把「指向我的边数」记成一个数，
   这个数是 0 的节点随时能开工。每做完一个节点，把它指向的节点的这个数减一，
   减到 0 就进队。这套流程 1962 年被 Kahn 写成算法，名字叫拓扑排序。
```

## 4 · 演示（读者：跟着走）

- 在贯穿例上带**全部中间步骤**走一遍，表格不省行
- 前几章步骤给全，后几章可以只给起点和终点（脚手架递减）
- 对应：认知负荷理论的样例效应、Renkl 的渐隐样例

```
❌ 用两遍扫描可以算出关键路径为 N9 → N10 → N11 → N12，总时长 7h。
✅ 一张 12 行的表：节点 / 估时 / ES / EF / LS / LF / slack，逐行填，
   slack 为 0 的四行加粗，读者能看到每个数是从哪两个数算出来的。
```

## 5 · 自己动手（读者：改 / 破 / 写）

- 2–3 个变体，每个带勾选框（`data-key`）
- 至少一个是「改参数看结果变没变」，至少一个是「把它弄坏」
- 答案折叠
- 对应：Merrill 应用、完成型问题、4C/ID 部分任务练习、Diátaxis 做中学

```
❌ 思考：关键路径有什么用？
✅ (a) 把 N9 估时从 3h 改成 1h，重算——关键路径挪到哪条线了？
   (b) 加一条边 N12 → N1，跑 Kahn 会发生什么？
   (c) 写出反向邻接表里 N1 那一行。
```

## 6 · 这里会错（读者：对照自己）

- 本章的误读，当场放；每条 = 错的说法 + 为什么错 + 对的判据
- 不攒到「常见误读」附录
- 对应：Make It Stick 的即时反馈、错误驱动学习

```
❌ （附录第 12 章）常见误读六则……
✅ 这里会错：ready 队列用 FIFO。先进先出忽略了关键路径——N9 晚开工 1 小时，
   整个工期晚 1 小时；判据：优先级 = 从本节点到汇的最长路径。
```

## 7 · 回头题（读者：用旧解新）

- 1–2 题，材料来自前面的章（越远越好），场景是本章的
- 答案折叠
- 对应：Make It Stick 的间隔 + 交错、Quantum Country 的间隔复习

```
❌ 复习：三条判据是什么？
✅ 回头题（第 1 章）：N11 的验证器是「/healthz 200 且 build hash == main HEAD」。
   按第 1 章的判据，这是声明还是动作？如果改成「跑一下部署脚本」呢？
```

## 8 · 攒规格（读者：记一行）

- 「本章给规格加了什么」：字段 / 规则 / 边类型，两三行的表
- 读者自己的规格表逐章累积；最后一章拿它对照参考规格
- 对应：Merrill 整合、UbD 迁移型表现任务、4C/ID 整任务

```
❌ （无此块；完整规格在第 10 章作为正文出现）
✅ 本章给规格加了：deps（正向边）+ 反向索引 / estimate / priority（按最长到汇路径自动算）/ 写入时环检测
```
